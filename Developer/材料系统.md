# 材料系统

> 材料 (金属/非金属)的 **数据**在脚本或事件里声明, **注册 / 模型 / 方块状态 / 标签** 全部由 Nebula Libs 在 Java 侧自动完成。
> 该系统的前身是整合包里的 `kubejs/startup_scripts/register/utils/Material.js`。

## 1. 时序: 它是什么时候跑的

```
模组构造阶段                       MaterialManager.bootstrap(bus)
      │
      ▼
NewRegistryEvent                  发布 RegisterMaterialEvent (Forge 事件总线)
  (所有模组构造完成,               └─ 同时桥接 KubeJS 的 NebulaEvents.registerMaterial
   注册表事件之前)                   → 收集 Java 与 JS 定义的材料
      │                            → MaterialRegistrar 加入延迟注册队列
      │                            → MaterialAssets 生成模型/方块状态/标签
      ▼
RegisterEvent                     MaterialRegistration 队列真正写入注册表
      │
      ▼
AddPackFindersEvent               注入内存资源包(模型 = 客户端, 标签 = 服务端数据)
```

要点:

* **不需要在主类里加载任何定义类**。Java 侧用一个 `@Mod.EventBusSubscriber` 监听事件即可。
* Java 与 JS 定义的材料会被合并处理, 同一个命名空间重复定义会记录错误并忽略后一个。
* 资源包是内存中的、隐藏且强制启用的, 不会出现在资源包界面里, 也不能被关掉。

## 2. 快速上手

### JS

在 `kubejs/startup_scripts` 下任意 `.js` 文件里:

```js
NebulaEvents.registerMaterial(event => {
	event.namespace("cmi")                // 命名空间只写一次, 与 Forge 事件一致

	// 参数: 材料名(不含命名空间), 挖掘等级
	event.create("chromium", MiningLevels.IRON)
		.color(0xEBE3E4, 0xB2ACAD)   // 主色, 副色
		.metal()                     // 加入 cmi:metals 标签
		.ingot()
		.plate()
		.dust()
		.nugget()
		.block()
		.molten()
		.dirty().clump().shard().crystal().slurry().dirtySlurry()
})
```

* 命名空间用 `event.namespace("cmi")` 设置 (与 Forge 事件一致), 之后 `event.create("chromium")` 会自动补成
  `cmi:chromium`;
  不设置命名空间时必须自己写完整 ID: `event.create("cmi:chromium")`。
* 事件对象上的方法: `namespace(String)` / `create(String)` / `create(String, IMiningLevel)` /
  `register(...)`(`create` 的别名, 与 Forge 事件方法名一致) / `materials()`。
* 旧写法 `new Material("chromium", "iron")` 改成 `event.create("chromium", MiningLevels.IRON)` 即可, 其余链式方法名字不变。
  (JS 侧方法名是 `create`, Forge 事件那边是 `register`, JS 的 `register` 是它的别名。)
* 迁移时记得 **删掉旧的 `utils/Material.js`**(那 4 个 `StartupEvents.registry(...)` 块), 否则 KubeJS 会注册同名物品导致注册表冲突。
* 现成的迁移结果见 `docs/migration/Materials.js`。

### Java

```java

@Mod.EventBusSubscriber(modid = CMICore.MODID)   // 默认就是 Forge 事件总线
public class CmiMaterials {
	@SubscribeEvent
	public static void onRegisterMaterial(RegisterMaterialEvent event) {
		event.namespace("cmi");                 // 可选: 之后可以只写材料名
		event.register("chromium", MiningLevels.IRON)
				.color(0xEBE3E4, 0xB2ACAD)
				.metal()
				.ingot()
				.plate()
				.block()
				.molten();
	}
}
```

## 3. 三组"接口 + 内置常量"

材料系统把"可扩展的部分"全部做成了接口, 而模组自带的那些放在对应的 `xxx`s 类里:

| 接口            | 作用                                                    | 模组内置                                                                                                                                                    |
|-----------------|---------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `IMiningLevel`  | 材料方块的挖掘等级(一个方块标签)                        | `MiningLevels`: `NONE / WOODEN / STONE / GOLD / IRON / DIAMOND / NETHER`                                                                                    |
| `IMaterialType` | 材料能生成什么(注册 ID 规则 / 贴图层 / 标签 / 内容工厂) | `MaterialTypes`: 18 个内置类型(锭 / 板 / 粒 / 粉 / 杆 / 齿轮 / 线材 / 棱镜 / 粗矿 / 脏粉 / 团块 / 碎片 / 晶体 / 金属块 / 粗矿块 / 熔融流体 / 矿浆 / 脏矿浆) |
| `IMaterialKind` | 材料类型的大类(默认注册流程 + 标签目录)                 | `MaterialKinds`: `ITEM / BLOCK / FLUID / SLURRY`                                                                                                            |

* 接口都带默认实现, 所以"只加一个同分类的新类型"几乎不用写逻辑。
* `MiningLevels` / `MaterialTypes` / `MaterialKinds` 就是"模组自带的类型", 也可以当工厂用 (`of(...)` / `item(...)` /
  `byName(...)`)。

### 加一个内置分类里的新类型 (例如"弹簧")

```java
public static final IMaterialType SPRING = MaterialTypes.item("spring")   // 物品分类
		.namePattern("%s_spring")
		.layers("spring/spring", "spring/spring_secondary")
		.overlay("spring/spring_overlay")
		.tags("mymod:springs", "mymod:springs/%s")
		.build();
```

JS 里同样可以 (纯声明式, 不需要写 Java):

```js
const SPRING = MaterialTypes.item("spring")
	.namePattern("%s_spring")
	.layers("spring/spring", "spring/spring_secondary")
	.overlay("spring/spring_overlay")
	.tags("cmi:springs", "cmi:springs/%s")
	.build()

NebulaEvents.registerMaterial(event => {
	event.namespace("cmi")
	event.create("chromium", MiningLevels.IRON).type(SPRING).ingot()
})
```

物品模型 / 方块状态 / 标签依旧自动生成 (贴图层写法与内置类型完全一致)。

### 加一个新分类 (例如气体)

分类需要自己实现注册流程, 其它 (标签目录)交给分类声明:

```java
public static final IMaterialKind GAS = MaterialKinds.of("gas")
		.tagDirectories("tags/mekanism/gas")
		.build();

public static final IMaterialType GAS_TYPE = MaterialTypes.of(GAS, "gas")
		.namePattern("%s_gas")
		.tags("mekanism:gases", "mekanism:gases/%s")
		.build()
		// 覆盖注册流程: 默认实现只认内置分类
		;
```

需要注册内容时, 覆盖 `register(Material)`, 并复用 `MaterialRegistrar` 里现成的公开流程:

```java
IMaterialType gas = new IMaterialType() {
	@Override
	public String id() {
		return "gas";
	}

	@Override
	public IMaterialKind kind() {
		return GAS;
	}

	@Override
	public List<String> tags() {
		return List.of("mekanism:gases", "mekanism:gases/%s");
	}

	@Override
	public boolean register(Material material) {
		registerGas(material.id(this), material.primaryColor());   // 自己的注册逻辑
		return true;                                               // 返回 false 就不生成标签
	}
};
```

`MaterialRegistrar` 里可复用的公开流程: `registerItem` / `registerBlock` / `registerFluid` / `registerSlurry`,
以及 `MaterialAssets` 的 `itemModel` / `blockAssets` / `bucketModel` / `tag`(标签目录自由指定)。

### 自定义挖掘等级

```java
IMiningLevel MY_LEVEL = IMiningLevel.of(ResourceLocation.parse("mymod:needs_my_tool"));
IMiningLevel FROM_TAG = IMiningLevel.of(MyModBlockTags.NEED_MY_TOOL);   // 也可以直接 lambda: () -> tag
```

```js
event.create("chromium", IMiningLevel.of("mymod:needs_my_tool"))       // 字符串会转成 ResourceLocation
// 或者用标签常量: IMiningLevel.ofTag(MyModBlockTags.NEED_MY_TOOL)
```

## 4. Material API

| 方法                                                                                   | 说明                                                                              |
|----------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| `color(int)` / `color(int primary, int secondary)`                                     | 主色(模型 layer0, tint 0)与副色(layer1, tint 1)                                   |
| `metal()` / `isMetal()`                                                                | 标记金属, 生成的内容加入 `<ns>:metals`                                            |
| `level(IMiningLevel)`                                                                  | 方块挖掘等级, 例如 `MiningLevels.IRON`                                            |
| `hardness(float)` / `resistance(float)` / `destroy(h, r)`                              | 方块硬度与爆炸抗性(默认 5 / 5)                                                    |
| `sound(SoundType)`                                                                     | 方块音效(默认 `SoundType.METAL`)                                                  |
| `textures(String namespace)`                                                           | 覆盖贴图命名空间(默认用模组自带的 `nebula_libs` 贴图)                             |
| `fluidTextures(String still, String flowing)`                                          | 覆盖熔融流体贴图(默认用 nebula_libs 自带贴图)                                     |
| `type(IMaterialType)` / `type(IMaterialType, boolean overlay)`                         | 声明任意类型(含自定义类型)                                                        |
| `ingot()` `plate()` `nugget()` `dust()` `rod()` `gear()` `wire()` `prism()` `rawOre()` | 内置物品类型, 支持 `xxx(false)` 关闭亮层                                          |
| `dirty()` `clump()` `shard()` `crystal()` `slurry()` `dirtySlurry()`                   | Mekanism 中间产物与矿浆                                                           |
| `block()` / `block(String model)`                                                      | 金属块(默认彩色贴图, 或指定模型, 例如 `immersiveengineering:block/storage_steel`) |
| `rawBlock()` / `rawBlock(String model)`                                                | 粗矿块                                                                            |
| `molten()`                                                                             | 熔融流体 + 桶                                                                     |
| `getItem(IMaterialType)` / `getBlock(IMaterialType)` / `getFluid(IMaterialType)`       | 按类型查询已注册内容                                                              |

### 4.1 快捷查询

等价于 `getItem(MaterialTypes.XXX)` / `getBlock(MaterialTypes.XXX)`, 材料没声明对应类型时返回
`Items.AIR` / `Blocks.AIR` / `Fluids.EMPTY`:

| 方法                                                                                                | 返回             | 对应类型             |
|-----------------------------------------------------------------------------------------------------|------------------|----------------------|
| `getIngot()` `getPlate()` `getNugget()` `getDust()` `getRod()` `getGear()` `getWire()` `getPrism()` | `Item`           | 对应的内置物品类型   |
| `getRawOre()`                                                                                       | `Item`           | `raw_<材料名>`       |
| `getDirtyDust()` `getClump()` `getShard()` `getCrystal()`                                           | `Item`           | Mekanism 中间产物    |
| `getBlock()`                                                                                        | `Block`          | `<材料名>_block`     |
| `getBlockItem()`                                                                                    | `Item`           | 金属块的物品形式     |
| `getRawBlock()` / `getRawBlockItem()`                                                               | `Block` / `Item` | `raw_<材料名>_block` |
| `getMolten()` / `getFluid()`                                                                        | `Fluid`          | 熔融流体(源)         |
| `getBucket()`                                                                                       | `Item`           | 熔融流体的桶         |

矿浆的返回类型是 Mekanism 的类, 所以放在兼容类里 (避免没装 Mekanism 时加载 Mekanism 的类):
`MekanismMaterialCompat.getSlurry(material)` / `getDirtySlurry(material)` / `getSlurry(material, type)`(不存在时返回
`null`)。

```java
// 例: 用某材料的锭做配方
Item ingot = MaterialManager.get("cmi:chromium").getIngot();
```

查询所有材料: `MaterialManager.materials()` / `MaterialManager.get("cmi:chromium")` /
`MaterialManager.materials("cmi")`。

## 5. 内置类型 / 注册 ID / 贴图约定

贴图 **随模组一起发布**, 位于 `nebula_libs:item/material/color/`(方块为
`nebula_libs:block/material/color/storage_blocks`, 熔融流体为 `nebula_libs:fluid/molten/`)。
颜色由 tint 决定, 所以这些贴图都是灰度图; 想让某个材料改用整合包自己的贴图, 用 `material.textures("cmi")` 把贴图命名空间切过去即可
(表里的路径就是切换后的相对路径)。

下表"贴图"列均相对 `<textureNamespace>:item/material/color/`。

| 类型            | 注册 ID                                     | 贴图                                                 | 层                        |
|-----------------|---------------------------------------------|------------------------------------------------------|---------------------------|
| `ingot()`       | `<m>_ingot`                                 | `ingot/ingot`, `ingot/ingot_secondary`               | + `ingot/ingot_overlay`   |
| `plate()`       | `<m>_plate`                                 | `plate/plate`, `plate/plate_secondary`               | + `plate/plate_overlay`   |
| `nugget()`      | `<m>_nugget`                                | `nugget/nugget`, `nugget/nugget_secondary`           | + `nugget/nugget_overlay` |
| `dust()`        | `<m>_dust`                                  | `dust/dust`, `dust/dust_secondary`                   | + `dust/dust_overlay`     |
| `rod()`         | `<m>_rod`                                   | `rod/rod`, `rod/rod_secondary`                       | + `rod/rod_overlay`       |
| `gear()`        | `<m>_gear`                                  | `gear/gear`, `gear/gear_secondary`                   | + `gear/gear_overlay`     |
| `wire()`        | `<m>_wire`                                  | `wire/wire`, `wire/wire_secondary`                   | + `wire/wire_overlay`     |
| `prism()`       | `<m>_prism`                                 | `prism/prism`, `prism/prism_secondary`               | + `prism/prism_overlay`   |
| `rawOre()`      | `raw_<m>`                                   | `raw_ore`                                            | -                         |
| `dirty()`       | `dirty_<m>_dust`                            | `dirty/0`, `dirty/1`(第二层不染色)                   | -                         |
| `clump()`       | `<m>_clump`                                 | `clump`                                              | -                         |
| `shard()`       | `<m>_shard`                                 | `shard`                                              | -                         |
| `crystal()`     | `<m>_crystal`                               | `crystal`                                            | -                         |
| `block()`       | `<m>_block`                                 | `<贴图命名空间>:block/material/color/storage_blocks` | -                         |
| `rawBlock()`    | `raw_<m>_block`                             | 同上                                                 | -                         |
| `molten()`      | `molten_<m>`(流体), `molten_<m>_bucket`(桶) | `nebula_libs:fluid/molten/still` `.../flow`          | -                         |
| `slurry()`      | `<m>_slurry`                                | Mekanism 干净矿浆贴图                                | -                         |
| `dirtySlurry()` | `dirty_<m>_slurry`                          | Mekanism 脏矿浆贴图                                  | -                         |

`+ overlay` 表示该类型支持第三层亮层, 默认开启, 用 `ingot(false)` 关闭。

## 6. 自动生成的标签

标签写入哪个目录由 `IMaterialKind#tagDirectories()` 决定: 物品 → `tags/items`, 方块 → `tags/blocks` + `tags/items`,
流体 → `tags/fluids`, 矿浆 → `tags/mekanism/slurry`。

| 类型          | 标签                                                                                                   |
|---------------|--------------------------------------------------------------------------------------------------------|
| 物品          | `forge:<type>s`, `forge:<type>s/<m>`                                                                   |
| 金属材料      | `<ns>:metals`(写入该分类的所有标签目录)                                                                |
| 粗矿          | `forge:raw_materials`, `forge:raw_materials/<m>`                                                       |
| Mekanism 产物 | `mekanism:dirty_dusts`, `mekanism:clumps`, `mekanism:shards`, `mekanism:crystals` 及 `.../<m>`         |
| 金属块        | 方块与物品: `forge:storage_blocks`, `forge:storage_blocks/<m>`; 粗矿块: `forge:storage_blocks/raw_<m>` |
| 方块挖掘      | `minecraft:mineable/pickaxe` + 挖掘等级标签(`minecraft:needs_iron_tool` 等)                            |
| 熔融流体      | `forge:molten_materials`, `forge:molten_<m>`, `tconstruct:molten_<m>`                                  |
| 矿浆          | `mekanism:clean` / `mekanism:dirty` 及 `.../<m>`                                                       |

## 7. 为什么需要"运行时资源包"

*材料是运行期数据*(脚本或事件才知道有哪些材料), 所以:

* Registrate / Forge 的 `model(...)` `blockstate(...)` `tag(...)` 都是 **datagen**, 只在开发期跑 `runData` 时生成 JSON,
  对运行期材料无效;
* Forge 1.20.1 也 **没有**运行期添加标签的 API;
* KubeJS 之前是靠自己的 `GeneratedResourcePack` 解决这件事的 (`modelJson` / `.tag()`)。

因此库做了等价的事: `MaterialAssets` 生成 JSON, `MaterialPack`(内存 `PackResources`)通过官方入口 `AddPackFindersEvent`
注入:

* `assets/<ns>/models/item/*.json` `assets/<ns>/models/block/*.json` `assets/<ns>/blockstates/*.json`
* `assets/<ns>/lang/en_us.json`(默认名称, 例如 `Chromium Ingot`)
* `data/<ns>/tags/items|blocks|fluids/*.json`
* `data/<ns>/tags/mekanism/slurry/*.json`

  (非原版注册表的标签目录是 `tags/<注册表命名空间>/<注册表路径>`, 见 `TagManager#getTagDir` 与
  `ForgeHooks#prefixNamespace`)
* `data/<ns>/loot_tables/blocks/*.json`(方块自己掉自己, 与 KubeJS 注册的方块行为一致)

颜色则通过 `RegisterColorHandlersEvent`(即 Registrate 的 `color()` 背后做的事)注册 tint。

> 生成资源包使用 `Pack.Position.BOTTOM`(仍然高于原版), 所以整合包/其它模组自己的模型与语言文件可以覆盖生成的内容;
> 标签是跨资源包合并的, 顺序不影响。

## 8. 常见问题

* **矿浆**: 只有加载了 Mekanism 才会注册, 否则跳过并在日志里警告 (此时也不会生成矿浆标签)。
* **自定义方块模型**: `block("mod:block/xxx")` 时不再生成方块模型, 方块状态与方块物品模型都指向该模型。
* **存储方块贴图**: `storage_blocks.png` 自带 CTM (`.mcmeta`)信息 (引用
  `nebula_libs:block/material/color/storage_blocks_ctm`), 需要相应 CTM 模组配合, 与旧脚本行为一致。
* **贴图来源**: 默认全部来自 `nebula_libs` 自带的灰度贴图, 整合包不需要再准备一份;
  只有想用自己画的贴图时才写 `material.textures("cmi")`(此时需要自己提供 `cmi:item/material/color/...`)。

  ```js
  event.create("chromium", MiningLevels.IRON).textures("cmi").ingot().plate()
  ```
* **命名空间**: 材料命名空间决定内容注册到哪个模组命名空间, 必须是实际存在的 modid。
* **重复定义**: 同一个材料 ID 定义两次, 第二次会被忽略并记录错误日志。
* **线材与配方脚本**: `wire()` 会生成 `forge:wires` 与 `forge:wires/<m>` 标签, 服务端脚本里的
  `#forge:wires/${metal}`(线材压制 / 统一 / TCon 铸造)会自动识别, 不需要额外写标签。
* **方块掉落**: 每个材料方块都会生成一份"自己掉自己"的掉落表; 想改成别的掉落物, 用数据包覆盖
  `data/<ns>/loot_tables/blocks/<方块ID>.json` 即可 (生成包优先级最低, 会被覆盖)。
* **默认名称**: 只生成 `en_us`(ID 转 Title Case, 例如 `chromium_ingot` → `Chromium Ingot`);
  中文名请自己写 `assets/<ns>/lang/zh_cn.json`, 同键会覆盖生成的英文名 (不同语言互不影响)。
* **注册时机**: 材料必须在 `RegisterMaterialEvent`(或 `NebulaEvents.registerMaterial`)里定义;
  注册表事件之后再往队列里加内容会记录明确错误, 不会静默丢失。
