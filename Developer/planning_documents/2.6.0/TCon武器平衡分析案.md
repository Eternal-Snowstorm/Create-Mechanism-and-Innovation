## 〇、裁定与统计口径

### 0.1 已裁定事项（用户确认, 作为本文设计约束）

1. 改动边界：kubejs + 数据包 + 允许改 Nebula Tinker 的 Java 逻辑并重新编译；不替换 TConstruct 本体。
2. 无敌帧清零机制：保留, 但近战侧要拿到**同等性质**的多段结算能力（对称但不同构）。
3. 策划案形态：并列多套方案, 各给完整数值与成本, 末尾给推荐。
4. 平衡口径：梯度分化 —— 贴脸弓与近战同档, 远距离明显衰减。
5. 弓的强度曲线：按「工业铁 → 不锈钢 → desh → ostrum」四级递增, 后期膨胀不得过剧；为此允许下调 `shadow_steel` 的 multishot 等级。
6. 近战侧：要有多种差异化强化思路（精准突击、回声连斩、溅射强化、破防重击）, 各自适配不同武器, 形成强度大致同一的 build 流派。
7. 精准突击的判定量是**时机**（在攻击冷却完成后的数个判定 tick 内发起下一次攻击, 判定达成即乘固定倍率 ×3.40）, 不是「同一目标」「击杀」, 也不叠层（m01859）。
8. **平衡锚点必须抬高**：毕业弓的单发数值若低于 20, 会明显弱于匠魂原版的弓箭, 失去使用整合包自定义弓材的意义；且毕业弓的射速不能削弱过多。
9. **1 级多重射击 = 3 箭**（代码确证：`BowAmmoModifierHook.getDesiredProjectiles` 返回 `1 + volatile`, `each_level = 2`）。因此毕业弓 3 箭全中 = 20 × 1.429 × 3 ≈ **86 DPS**, 这也就是**毕业近战武器的 DPS 锚点**。
10. 四个近战技能必须是**材料专有技能**（不占用升级/能力槽）, 并且各自再配针对性强化件, 形成可选 build；它们是「把近战提到裸弓水平」的基础, 不是终局。
11. 弓的 build 线以 Nebula 的 `converge`（收束）为核心继续设计；自定义修饰符的获取途径统一在 `kubejs/server_scripts/recipes/misc/tconstruct/Modifier.js` 注册。
12. **平衡范围收敛为十件武器**（m02098）：`dagger` / `sword` / `cleaver` / `hand_axe` / `broad_axe` / `scythe` / `sledge_hammer` / `javelin` / `longbow` / `crossbow`；`kama` / `vein_hammer` / `battlesign` / 镐类不在范围内, 技能照常生效但不作验收。验收分三档：**单体档 85.7（±15% ⇒ 73~99）** ／ **AOE 档 3 目标 85.7** ／ **团队档 55~70**。
13. **标枪与弩各自独立成流派**（m02098 裁定 2）：标枪 = 投掷穿刺（`cmi:impale`, 钛载体）、弩 = 装填齐射（`cmi:volley`, 以太弓臂）；短柄斧新增「处刑」（`cmi:execution`, 钒载体）；**镰 `scythe` 从工具改回武器**, 按 AOE 档验收（原 D2 结案）。
14. **低基础补偿一律按攻速缩放倍率**（m02098 裁定 4）：破防重击追加 `500% × (0.9 / attackSpeed)`、处刑追加 `900% × (0.9 / attackSpeed)`, 不通胀攻击力。

> 第 8、9 两条把弓的两端钉死了：单发 ≥20 且射速不降 ⇒ 弓的 DPS 下限被钉在「20 × 射速 × 箭数」= 86；这也直接废掉了「把弓削到与近战 30 同档」这条最简单的路子。本文全部弓侧设计（第 4、5 章）与近战侧设计（第 6 章）都是在这两个数字之间反解出来的。

### 0.2 统计口径（所有 DPS 均按此口径, 避免歧义）

- 目标：单体、无护甲、无抗性、满血。
- 连续输出：弓按拉满蓄力循环, 近战按满冷却点击。
- **基准口径为「不暴击」**。理由：用户实测「耐热金属近战 30 DPS」「中期黄铜弓 30 DPS」均与不暴击值吻合；拉满必暴击的箭（`if (charge == 1.0f) arrow.setCritArrow(true)`）在原版 `AbstractArrow` 里是「追加 `random.nextInt(i/2+2)`」即期望 **+25%**, 本文单列为「暴击口径」而不并入基准。
- 弓的距离口径分三档（几何推导见 7.2）：
  - **满伤圈** = ≤**1.7 格**：3 支箭全部落在目标的碰撞箱内。3 箭在 TConstruct 里本来是**垂直**扇形（`ModifiableBowItem.java:242-243` 用 `living.getXRot() + angle`）, 但 **Nebula Tinker 的 `ModifiableBowItemMixin` 把散布平面无条件换成了水平**（把俯仰偏移搬到偏航）, 所以容差是目标的**半宽 0.3**, 而不是半高 0.95。
  - **单箭区** = 1.7 格以外：只有中央一箭命中 ⇒ 单体 DPS 掉到 **28.6**（L4）。`converge` 的作用就是把满伤圈拉长（见 5.2）。
  - **`converge` 的收敛是有限的**：1~4 级按 `(5 − L)/5` 缩小水平角（±8 / ±6 / ±4 / ±2° ⇒ 2.13 / 2.85 / 4.29 / 8.60 格）；**5 级及以上是完全收敛** —— `ModifiableBowItemMixin.java:31-39` 的 `else` 分支把 `xRot` 换成玩家视角本身、`yRot` 原样（原版把散布加在 `xRot` 上, 传入的 `yRot` 本身无偏移）, 于是 **3 支箭全部沿准心射出、轨迹完全重合**, 满伤圈不再受几何限制。⇒ **开放 5 级等于取消距离分层**, 本文用配方上限把它锁在 4 级（8.1 ②, D12）。
  - **近战上限** = **3.0 格**（MC `entity_interaction_range` 默认值）。⇒ 近战能打到的 3 格之内, 弓只有 1.7 格是满伤, 剩下 1.3 格是近战的反超区间。
- 不含药水、饰品增益、Nebula 暴击系统之外的第三方加成。

## 一、结论摘要

1. **失衡的开关是「受击无敌帧清零」, 而放大器是多重射击等级。**
   原版 `LivingEntity.hurt` 的规定是：若目标 `invulnerableTime > 10` 且本次伤害不大于上次, **直接返回 false、一点血都不掉**。`InvincibleFrameEgregatorItem`（Curios 饰品）与 `shadow` trait 都在 `LivingEntityHurtEvent` 里把 `target.invulnerableTime = 0`, 于是同一轮齐射的每一支箭都变成全额结算。裸弓（无清零点）L4 贴脸只有 **21.4**, 正好与近战同档；一旦开清零点 + `shadow`, 就变成 **128.6~157**。
2. **因此弓侧只需要两件事（材料参数 + 限箭数）, 且成本全案最低。**
   - **限制箭数**：`shadow_steel` 的 `ranged: multishot 2 → 1` ⇒ N 从 5 回到 3。`multishot.json` 的 `each_level = 2` **不改**（1 级本就是 3 箭, 改它会让玩家熟悉的「3 箭齐射」变成 2 箭）。
   - **材料上调**：紫金 `velocity 0.7→1.1`（单箭 = 20）、戴斯 `0.45→0.6`（14）、不锈钢 `0.2→0.3`（10）；`drawSpeed` 只升不降 ⇒ 射速 **1.333 / 1.333 / 1.429 / 1.429**。
   - 结果（贴脸 3 箭全中 / 远距 1 箭）：**32.0 / 40.0 / 60.0 / 85.7** 与 **10.7 / 13.3 / 20.0 / 28.6**。这个 85.7 就是 m00786 给出的近战锚点 86 的来源, 两端自洽。
3. **近战要到 86 需要三个部件：F0 基线 + 材料专有技能 + 下限保护。**
   - **F0 基线**（`cmi:heavy_edge`, tier4 挂 2 级 = +3.0 攻击力）⇒ tier4 剑裸值 19.4 → **25.0**。只做技能不做 F0, 最好也只到 74, 仍差弓 14%。
   - **材料专有技能**（八个：五个近战 + 三个远程, 各挂一种新注册的载体材料、**不占槽位**）：近战走 `melee_harvest` 组 —— `precision_strike` / `echo_slash` / `glow_splash` / `guard_break` / `execution`；远程 —— `impale`（标枪, `melee_harvest`）与 `volley`（弩, `ranged` 的 `limb`）。倍率 **×3.40 ~ ×9.00**（处刑与破防按攻速缩放）。按 m02098 的武器归属算基础档：剑 精准 **85.0** / 回声 **85.8**, 匕首 回声 **85.8**, 短柄斧 处刑 **82.0**, 标枪 投掷穿刺 **84.7**, 弩 装填齐射 **86.1**。⇒ 按 m02098 的十件武器口径汇总：**单体档**剑 **85.0 / 85.8**、匕首 **85.8**、短柄斧（处刑）**82.0**、标枪（投掷穿刺）**84.7**、弩（装填齐射）**86.1**、长弓 **85.7** ⇒ 全部落在 **82~86** 的同档区间；**AOE 档**劈刀 3 目标 **139.4**、镰 3 目标 **82.5**；**团队档**板斧 **67.9**、大锤 **57.2**、劈刀 **61.3**（破防按攻速缩放, 见 6.8b）, 它们的兑换币是「全队受到的伤害 +20%」（6.5 / 6.6 / D18）。
   - **下限保护（floor）**：每次追加取 `max(百分比 × 本次伤害, floor)`。低基础武器（匕首钨钢刃单击 6.4、kama 4.7、镰 7.0）靠 floor 被托起（匕首 `echo_slash` = **85.8**, floor 取 8）, 高基础武器（剑 17.5）碰不到 floor。**这是解决「tier4 裸 DPS 跨度 3.1 倍」的唯一正确手段** —— 跨度是加法项缺失造成的, 只能用加法补, 不能用乘法补（6.1 有完整论证）。
4. **技能挂材料 = 流派入口；强化件 = 上限；近战没有消耗品层。**
   - 材料层（免费, 锚点本身 82~86）⇒ 玩家选「铬剑 / 钨钢剑 / 红钕劈刀 / 铂锤 / 钒短柄斧 / 钛标枪 / 以太弓臂」就是选流派, 不需要占槽、不需要额外材料；
   - **投入层**（可反复追加, 目标 **110~130**）：十个针对性强化件（节拍窗、终式、回响枪、迟响、焦光、震核、崩解、落锤、重刃、延展）。注意：本整合包的 `tconstruct:writable` / `tconstruct:draconic` 配方取消了原版等级上限（每级 +1 升级槽 / +1 能力槽, 见 5.1）, **毕业期槽位可以无限购买**, 所以这一层的真实成本是材料而不是槽位；
   - 消耗品层：**近战没有**。所以近战的投入层必须给到纵向加伤（弓的纵向在消耗层）, 但设计上限卡 130 以内 —— 否则「永久有效的 150」会压过「每发付费的 124」。这个上限是设计纪律、不是机制保证（D15）。
5. **弓的 build 只有两条路线, 且互斥（第 5 章）—— 不给锚点开后门。**
   - **齐射（收束）**：`converge` 把满伤圈从 **1.7 格**拉到 2.1 / 2.9 / 4.3 / **8.6** 格。纯改距离、不改伤害。**5 级是完全收敛**（3 箭轨迹完全重合、满伤圈不再受几何限制）—— 那等于取消距离分层, 因此本文把配方上限锁在 4 级（`Modifier.js` 一行 `level(1,5) → level(1,4)`, 零 Java 改动, D12）。
   - **贴身散射（新增）**：`cmi:point_blank` 只在 6 格内生效 —— 每支箭命中时对命中点 1.5 格内最多 2 个其他生物溅射 40%/55%/70% × 单箭伤害。单体不变（85.7）, 3 目标 **205.7**。对照近战溅射强化（m01984 后只挂重武器：劈刀单体 57.1 / 3 目标 **139.4** / 6 目标 262.1）⇒ **3 目标弓反而更高**, 这是刻意的：近战的群伤优势必须用重武器的单体损失去换。**与齐射互斥**：装了 `converge` 则散射全部失效 —— 收束把三箭压到同一点, 箭爆会全砸在同一片区域, 机制上互相抵消。
   - 弹种特化（光辉石箭头 `keen 2` ⇒ 单箭 29、L4 **124.3**）不算流派, 它是齐射的**消耗层纵向通道**, 每发付账, 随时可停。
6. **三条仍存在的结构性不对称, 本文选择「接受」而非「抹平」。**
   - **距离**：**1.7 格内**两侧平手（弓 85.7 vs 近战单体主武器 85.0~85.8）；**1.7~3.0 格近战反超 2.7~3.0 倍**（弓只剩 28.6, 近战仍是 85.0~85.8）；**3.0 格外近战归零、弓独占**（裸弓 28.6, 装 converge 4 后满伤圈 8.6 格）。⇒ **弓的强不是「远距离强」, 而是「贴脸 1.7 格内、目标不太小」的强**：这也正是「贴身散射」这条流派存在的理由, 也是 m00431 观察的原始形态。
   - **多目标**：裸弓上限 85.7（3 箭全中同一目标）；散射路线在 6 格内可把 3 目标做到 205.7、6 目标 265.7（装 `scatter_lens`）。对照近战溅射强化（劈刀）3 目标 139.4、6 目标 262.1 ⇒ **3 目标弓更优、6 目标基本平手（265.7 vs 262.1）**。按 m01984, 群体已不是近战的独占生态位, 而是「重武器用单体损失换来的对等值」；两侧都不存在「单体强且群体最强」的配置。
   - **镰 scythe（m02098 后改判为武器, D2 结案）**：裸值 8.1, 但 `circle_melee 2.0` 对每个目标各走一次 `performAttack`, 所以精准突击的 ×3.40 **逐目标结算** ⇒ 单体 27.5 / **3 目标 82.5**；回声连斩 25.5 / 3 目标 76.5。按 **AOE 档（3 目标 85.7）** 验收通过, 不再以「工具」豁免。
   - **四件新增对象的档位**：短柄斧（处刑, 82.0）、标枪（投掷穿刺, 84.7）、弩（装填齐射, 86.1）属单体档；板斧 / 大锤 / 劈刀属团队档。详见 6.8b 与 7.5。

## 二、已确证的数值链路

### 2.1 弓（来源 ModifiableBowItem.java:171-260, ModifiableLauncherItem.java:310）

- 蓄力: `charge = getToolCharge(tool, chargeTime)`, 拉满 = 1.0。
- 射速: `drawtime = ceil(20 / DRAW_SPEED)`（tick）, 射速 `R = 20 / drawtime`。
- 箭初速: `power = charge × VELOCITY(弓)`, `arrow.shootFromRotation(..., power × 3.0f, inaccuracy)`, 随后箭自身 `VELOCITY`（默认 1.0）再乘一次。
- 单箭伤害: `baseDamage = 箭PROJECTILE_DAMAGE - 2.0 + 弓PROJECTILE_DAMAGE`, 命中时 `damage = ceil(本tick位移 × baseDamage)`。裸箭 PROJECTILE_DAMAGE = 2.0（`ToolStats` 默认值）, 长弓 base_stats 未设该 stat（默认 2.0）⇒ **baseDamage = 2.0**, 即单箭 ≈ `ceil(6 × VELOCITY总)`。
- 箭数: `N = 1 + 2 × multishot等级`（`multishot.json` 的 `each_level: 2`）。
- 散布: `getAngleStart(N) = -5(N-1)`, 循环内每支 `+10°`。N=3 ⇒ -10/0/+10；N=5 ⇒ -20/-10/0/+10/+20。
- 随机散布: `inaccuracy = 3.0 × (1/ACCURACY - 1)`（ModifierUtil.java:194-196）。ACCURACY 默认 0.75 ⇒ 1.0；封顶 1.0 ⇒ 0。
- 暴击: 拉满必暴击（`charge == 1.0f ⇒ setCritArrow(true)`）。

**几何命中数**（决定距离衰减）: 第 i 支箭的横向偏移 = `距离 × tan(间隔角)`。僵尸半宽 0.3 格:

- N=1（无多重射击）: 只有中央一箭, 任何距离都全中 —— 这是四个弓把都未挂 `multishot` 时的状态。
- N=3（±10°）是本文的目标配置, 命中几何见 0.2 与 7.2。
- N=3（±10°）: 1 格 0.18（全中）、2 格 0.35（丢 2 支）、3 格 0.53（只中 1 支）。
- N=5（±20°）: 0.5 格 0.18（全中）、1 格 0.36（中 3 支）、1.5 格 0.55（中 1~2 支）、3 格（只中 1 支）。

⇒ 「贴脸」的严格定义是 **≤1 格**；超过 1.5 格, N=5 的额外箭几乎全部落空。用户所说「裸弓状态符合近战强力、远距离衰减」在代码层完全成立。

### 2.2 近战（来源 ToolAttackUtil.java）

- 单击伤害 = `ATTACK_DAMAGE` 属性值（`ToolAttackContext.applyAttributes`）, 由工具 stats 的 `attack_damage` + 玩家基础 1 组成；材料 head 的 meleeAttack 平加、handle 的 meleeDamage% 按部件 scale 乘算。
- 冷却门限（:158-166）: `cooldown < 1.0` 时 `damage ×= 0.2 + 0.8 × cooldown²`。满冷却点击才是全额。
- 暴击（:90-103）: 下落 + 满蓄 + 不在地面 + 不冲刺 ⇒ ×1.5, 并抛 `CriticalHitEvent`（Nebula 在此改倍率）。
- 攻速（:260-264）: `speed = ATTACK_SPEED`, `time = round(20/speed)`, 命中后 `target.f_19802_ = (f_19802_ + time) / 2`。**近战不吃 i-frame 惩罚**, 因为下一次攻击间隔 ≈ time。
- 现成的无 i-frame 伤害工具（:336-347）: `hurtNoInvulnerableTime(Entity, LivingEntity, DamageSource, float)`, 以及 `attackEntitySecondary(...)` 封装。**这是实现「近战多段」的官方正确姿势。**

⇒ 近战 DPS = 单击 × ATTACK_SPEED, **每秒命中次数被攻击冷却锁死在 1.0~2.0 之间**。这是近战无法靠数值追上弓箭的根本原因：想追 150 DPS 需要单击 75~94, 必然秒杀普通怪并造成全局攻击力通胀。

### 2.3 两条清零点（失衡的唯一开关）

1. `InvincibleFrameEgregatorItem`（Curios 饰品, analysis/_nb_out/.../item/InvincibleFrameEgregatorItem.java:34-38）
   - 触发: `source.is(DamageTypeTags.IS_PROJECTILE)` 且 `source.getEntity() instanceof Player` 且 `getDirectEntity()` 为 null 或 Player 且玩家 Curios 中有该物品。
   - 动作: `target.f_19802_ = 0`。
   - 效果: 下一支箭走 `invulnerableTime <= 10` 分支 ⇒ **全额结算**。饰品单独就能把整个齐射全部放开。
2. `Shadow`（暗影钢 trait, analysis/_nb_out/.../modifier/Shadow.java:13-18）
   - 触发: `BasicModifier.onLivingHurtEvent` 只判断 `source.getEntity() instanceof Player` 且主手是 IModifiable ⇒ **弓箭命中也会触发**。
   - 动作: `target.f_19802_ = 0; target.hurt(attacker.damageSources().magic(), level + 1)`（attacker 实为受击者自身, 即无归属魔法伤害）。
   - 双重效果: 额外 +3 伤害（level 2）, 且那个嵌套 `hurt(3)` 把 `lastHurt` 从 22 压到 3 ⇒ 后续每箭只被吃掉 3 点, **剩 19 全额结算**。

**关键推论**: 只装饰品不装暗影钢, 齐射已能全箭全额；装暗影钢则每箭再 +3 且吞伤更少。两者叠加才出现 5 箭 × 22 的峰值。

### 2.4 材料在弓部件上的贡献（TConMaterial.js 实测参数）

弓只有两个部件带数值: `bow_limb`（弓臂, 走 LimbMaterialStats）与 `bow_grip`（弓把, 走 GripMaterialStats）。**两者都不提供 ANY 伤害属性**, 弓的伤害全部来自箭与 VELOCITY。弓把的「强度」完全来自它挂的 trait（multishot）。

可作弓把（grip）的材料与参数 `grip(accuracy, durability%, meleeDamage)` 及现有 ranged trait:

## 三、失衡的定量拆分

### 3.1 三个场景的复算（与用户实测对账）

场景甲: 中期「黄铜弓把 + 工业铁弓臂×2」, multishot 1 ⇒ N=3（现 each_level=2）

- VELOCITY = 1.0 + 0.2 = 1.2 ⇒ 箭速 3.6 ⇒ 单箭 ceil(7.2) = 8
- DRAW_SPEED = 1.0 + 0.4 = 1.4 ⇒ drawtime 15 ⇒ R = 1.333
- 有清零点（5 箭全中口径应为 3 箭）: 8 × 1.333 × 3 = **32 DPS**（实测 30 ✓）
- 无清零点（只结算 1 箭）: 8 × 1.333 = **10.7 DPS**

场景乙: 后期「暗影钢弓把 + 紫金弓臂×2」, multishot 2 ⇒ N=5

- VELOCITY = 2.4 ⇒ 箭速 7.2 ⇒ 单箭 ceil(14.4) = 15
- DRAW_SPEED = 1.5 ⇒ drawtime 14 ⇒ R = 1.4286
- 有清零点 + shadow: (15 + 3) × 1.4286 × 5 = **128.6 DPS**（叠暴击与命中率浮动后实测 150 ✓）
- 有清零点、无 shadow: 15 × 1.4286 × 5 = 107.1 DPS
- 无清零点: 15 × 1.4286 = **21.4 DPS**

场景丙: 后期「耐热金属剑」

- ATTACK_DAMAGE ≈ 3.0（剑 base）+ 6.5（耐热金属 head meleeAttack）= 9.5, 经双柄 1.3 倍 ⇒ 12.35, 加玩家基础 1 ⇒ 13.35
- ATTACK_SPEED ≈ 1.45（base 1.6, 手柄 -0.15）
- 不暴击: 13.35 × 1.45 = **19.4 DPS**；暴击浮动后 ≈ 29（实测 30 ✓）

### 3.2 拆分的结论

- 单次结算伤害两者几乎相同: 弓 8~15（暴击 12~22）, 近战 13.35（暴击 20）。
- **5 倍差距全部来自「每秒结算次数」**: 弓 3~5 箭/发 × 1.33~1.43 发/秒 = 每秒 4~7 次全额结算；近战每秒 1.45 次。
- 而「每秒 4~7 次」只在清零点存在时成立。**清零点 = 唯一的 5 倍乘数。**

### 3.3 由此得到的平衡原则（经 m00641 / m00786 修正后）

- 削弓: 最便宜的杠杆是**限制箭数**（暗影钢 `multishot 2→1`）, 不是动清零点、也不是动材料数值。初版认为「只需处理清零点」已在 4.4 被否证 —— 清零点关掉会把 L4 打到 28.6, 违反 m00641「单发 ≥20、射速不削」与 m00786「毕业 ≈86」两条硬锚点。
- 抬近战: 必须新增「多段结算通道」, 因为攻速被冷却锁死；纯加攻击力会把普通怪秒杀并通胀（5.6 的定量否证: 到 86 需约 29 级 `heavy_edge`, 单击 60 会让僵尸/骷髅/末影人一刀必死）。
- 两者要「对称」但不「同构」: 弓的多段是**一次发射产生多个投射物**（空间分离）, 近战的多段是**一次挥击产生多次结算**（时间分离）。二者最终对齐的是「每秒等效结算次数」, 而不是叠加规则本身。

### 3.4 现状与目标的逐格对账

| 场景 | 现状（含清零点） | 目标（本文方案） | 削减比 |
| --- | --- | --- | --- |
| L1 工业铁弓臂×2 + 黄铜弓把 | 32.0 | **32.0** | 1.00（不动, 作为起点） |
| L2 不锈钢弓臂×2 + 弓把 | 10.6（无 multishot）→ 挂 1 级后 31.8 | **40.0** | 上调 |
| L3 desh 弓臂×2 + 弓把 | 15.0 → 挂 1 级后 45.0 | **60.0** | 上调 |
| L4 紫金弓臂×2 + 暗影钢弓把 | 128.6~157（N=5 + shadow） | **85.7**（N=3） | **0.55~0.67** |
| 近战 tier4 剑（裸） | 19.4 | **25.0**（加 F0） | — |
| 近战 tier4 剑 / 匕首（带流派） | 19.4 / 13.3（无流派） | **85.0 / 85.8** | 新增 |

- 上面这张表就是全案要交的账: 弓的削减**只在 L4 一处**（N 5→3 与单箭 15→20 相互抵消后净降 33%~45%）, L1~L3 全部是上调；近战的提升靠新增机制而非现有数值。
- 之所以敢在 L1~L3 上调, 是因为它们当前的值（10.6~15.0 无 multishot）远低于同 tier 近战, 属于「本就该修」的缺口；真正的膨胀只发生在 L4, 而 L4 的问题来自 N=5 而不是单箭值。

## 四、弓的四级曲线设计

### 4.1 参数化公式

设四级材料为 `L1 = industrial_iron、L2 = stainless_steel、L3 = desh、L4 = ostrum`, 标准配装为「双同级弓臂 + 同级弓把 + 麻绳弓弦」, 则:

- `VELOCITY(V) = 1.0 + 2 × limb.velocity`
- `DRAW_SPEED(D) = 1.0 + 2 × limb.drawSpeed`
- `drawtime = ceil(20/D)`, `R = 20/drawtime`
- `单箭 = ceil(6V)`（baseDamage = 2.0）
- `N = 1 + 2 × multishot 等级`（`multishot.json` 的 `each_level` **原生就是 2, 本方案不改它**）⇒ **1 级 = 3 箭、2 级 = 5 箭**
- `贴脸DPS = 单箭 × R × N`（3 箭全部命中并全部结算）、`= 单箭 × R`（无清零点）
- `远距DPS = 单箭 × R`（几何上只中 1 箭, 与清零点无关）

`N` 的来历已由代码确证: `BowAmmoModifierHook.getDesiredProjectiles = 1 + volatileData.getInt(MULTISHOT)`, 而 `MULTISHOT` 由 `new VolatileIntModule(..., LevelingInt.eachLevel(2))` 写入。所以「1 级多重射击 = 额外 2 箭 = 共 3 箭」是原生行为, 任何「把 `each_level` 改成 1 让 N=2」的推导都是错的（本文件此前的 42 版口径即因此作废）。

### 4.2 现状值（不动任何参数时的裸弓）

- L1 工业铁（把无 multishot）: V=1.2, 单箭 8, D=1.4, R=1.333 ⇒ 贴脸 10.7 / 远距 10.7
- L2 不锈钢（把无 multishot）: V=1.4, 单箭 9, D=1.2, R=1.176 ⇒ 贴脸 10.6 / 远距 10.6
- L3 desh（把无 multishot）: V=1.9, 单箭 12, D=1.3, R=1.25 ⇒ 贴脸 15.0 / 远距 15.0
- L4 ostrom（把无 multishot）: V=2.4, 单箭 15, D=1.5, R=1.4286 ⇒ 贴脸 21.4 / 远距 21.4

（现状四个弓把均未挂 `multishot` trait, 故 `N=1`。）

⇒ **没有 multishot 时, 四级曲线是 10.7 / 10.6 / 15.0 / 21.4, 极度平缓但整体偏低**；L4 单发仅 15 点, 低于「毕业弓单发 ≥ 20」的锚点（用户裁定 m00641）：原版满蓄力箭约 6 点, 毕业弓若只有 15 点, 玩家会直接回去用原版弓, 自定义弓材失去存在意义。同时 L2 因 `drawSpeed` 下降而几乎不涨, 曲线出现平台。

### 4.3 目标曲线（按「毕业弓单发 ≥ 20、锚点 ≈ 86」重修）

**三条锚点约束（用户裁定 m00641 + m00786）**

- 毕业弓（L4）**单发伤害 ≥ 20**: 低于此值明显弱于匠魂原版弓, 自定义弓材失去意义。
- **射速不得削弱**: 四级射速只允许持平或提高。`DRAW_SPEED` 越高 `drawtime` 越短, 所以「提高 drawSpeed」是提速、「降低 drawSpeed」才是削射速, 本方案全部取向提速。
- **毕业弓贴脸 DPS 锚点 ≈ 86**（用户 m00786 直接给出）: 由 `单发 20 × 射速 1.429 × 3 箭 = 85.7` 得到, 即「1 级多重射击 = 3 箭全部结算」。这个数字同时锁定了近战侧的毕业锚点（见 6.1）。

**由锚点反解的参数**

- 单箭 = `ceil(6V) ≥ 20` ⇒ `V ≥ 3.1667` ⇒ 双弓臂的 `limb.velocity ≥ 1.0833` ⇒ 紫金弓臂 `velocity 0.7 → 1.1`（V=3.2, 单箭 20）。
- 为让曲线从 8 平滑爬到 20: desh 弓臂 `velocity 0.45 → 0.6`（V=2.2, 单箭 14）、不锈钢弓臂 `velocity 0.2 → 0.3`（V=1.6, 单箭 10）。
- 为让射速只提不降: 不锈钢弓臂 `drawSpeed 0.1 → 0.2`（R 1.176 → 1.333）、desh 弓臂 `drawSpeed 0.15 → 0.25`（R 1.25 → 1.429）。两处都是提速。
- 多重射击: `multishot.json` 的 `each_level` **保持原生 2 不动**；改为在四级弓把（工业铁 / 不锈钢 / desh / 紫金）的 `ranged` 组各挂 `multishot 1` ⇒ **`N = 1 + 2×1 = 3`**。暗影钢把 `multishot 2 → 1`（用户已允许）, 黄铜把维持 1。

**结果（`N=3`, 3 箭全部结算；不启用 4.4-B3 递减）**

- L1 工业铁 `limb(0, 0.2, 250, 0.1)`: V=1.2, 单箭 8, D=1.4, R=1.333 ⇒ **贴脸 32.0 / 远距 10.7**
- L2 不锈钢 `limb(-0.05, 0.2, 800, 0.3)`: V=1.6, 单箭 10, D=1.4, R=1.333 ⇒ **贴脸 40.0 / 远距 13.3**
- L3 desh `limb(0.15, 0.25, 1280, 0.6)`: V=2.2, 单箭 14, D=1.5, R=1.429 ⇒ **贴脸 60.0 / 远距 20.0**
- L4 紫金 `limb(0.35, 0.25, 1420, 1.1)`: V=3.2, 单箭 20, D=1.5, R=1.429 ⇒ **贴脸 85.7 / 远距 28.6**

⇒ 四级曲线 **32.0 → 40.0 → 60.0 → 85.7**, 跨度 2.7 倍、全程单调、无平台；远距 **10.7 → 13.3 → 20.0 → 28.6** 同样单调。毕业弓单发 20、贴脸 85.7, 两条锚点同时达成。

**为什么不再启用 4.4-B3 递减结算**: B3 把 3 箭的等效箭数压到 `1 + 1/2 + 1/3 = 1.833`, L4 会掉到 `20 × 1.429 × 1.833 = 52.4`, 与「毕业弓锚点 86」直接冲突。⇒ **B3 降级为「日后若嫌 86 过高时」的可调旋钮**（拧到 `×1.833` 即 52.4、拧到 `×2.4` 即 68.6）, 不再是落地必做项。同理 B1/B2 也降级为备选。

对照近战同 tier（裸装、无流派、含 `cmi:heavy_edge` 基线（见 6.1））: tier2 ≈ 11、tier3 ≈ 18.5、tier4 ≈ 25。

- 裸装近战打不过同级弓（tier4 25 vs L4 贴脸 85.7）——弓的优势是「投入材料即得」, 近战的优势必须由机制（第六章）提供, 这是本方案的基本分工。
- **近战带流派后 tier4 目标 86**（见 6.1 三档锚点）, 与弓 L4 贴脸 85.7 同档, 与裁定 4「贴脸平手」一致。

**这套曲线只靠数据包 + TConMaterial.js 改动（3 处 limb 参数 + 5 处 multishot 挂载）即可达成, 不需要新机制。** 若清零点原样保留且 multishot 仍为 2 级（暗影钢配紫金臂的现状）, 上式会退化为「×5 箭」的 150, 也就是用户实测的现状。

### 4.4 清零点的处理：保留为基准, 另给三档降档旋钮

**基准口径: 清零点完全保留、3 箭全部结算**

理由（本节最重要的判断）:

- 清零点本身不是失衡源。它只是把「多箭齐发」从「命中率优势」变成「单体 DPS 优势」；当单箭只有 8~15 时, 即便 5 箭全中也只有 53~75 的来源。真正把数字推到 150 的, 是 `N=5`（暗影钢 `multishot 2`）与 `单箭 15` 同时成立。
- 本方案把 `N` 从 5 锁到 3（暗影钢 `multishot 2 → 1`、四级弓把各挂 `multishot 1`）、把单箭上限锁到 20, 峰值即落到 **85.7**, 也就是用户给出的 86 锚点。
- 用户裁定 2 要求「保留机制但对称化」⇒ 近战侧必须拿到同一把钥匙。但这里的对称化**不是给近战清零帧, 而是给近战多段**：`ToolAttackUtil` 第 260~264 行本来就会把目标无敌帧压到与攻击间隔同量级, 所以近战已不吃无敌帧惩罚, 「清零」对近战零收益。真正等价的能力是「一次挥击产生多次独立伤害」——见 6.4 回声连斩与 6.6 破防重击, 二者都用现成的 `ToolAttackUtil.hurtNoInvulnerableTime`。

**三档降档旋钮（若日后觉得 86 仍偏高时单独启用；互不依赖、可叠用）**

#### 旋钮 N1 递减结算

- 动作: 在 `LivingHurtEvent` 中, 对同一目标同一 tick 内的第 n 次投射物命中, 把 `event.setAmount(amount / n^k)`。
- 等效箭数 `E(N,k) = Σ(n=1..N) n^(-k)`, `N=3` 时: `k=0 ⇒ 3.00`、`k=0.5 ⇒ 2.28`、`k=1 ⇒ 1.83`。
- 对应 L4 `20 × 1.429 × E` ⇒ **85.7 / 65.2 / 52.4**。`k` 是一个连续旋钮, 从「完全不递减」到「几乎只算首发」都能调。
- 成本: 约 40 行事件处理器 + 每 tick 清理 Map；**不需要改 TConstruct, 也不需要改箭 NBT**。
- 风险: 「同一 tick」要用 tick 号判定而不是真实时间；建议只对 `IS_PROJECTILE` 且 `getEntity() instanceof Player` 生效, 避免误伤其他模组。

#### 旋钮 N2 齐发共帧

- 动作: 清零点保留, 但「同一次射击」只允许第一箭完整结算。发射时给每箭写 `persistentData` 的 `shotId`（`tick + shooterUUID`）, Nebula 在 `LivingHurtEvent` 维护 `(targetUUID, shotId) → 已结算`, 第二次起 `event.setAmount(0)`。
- 结果: 单体等效 1 箭 ⇒ L4 **28.6**；但一支箭打一个目标 ⇒ **多目标时各自全额结算**, AOE 价值完整保留。
- 成本: 1 处 mixin/拦截写 `persistentData` + 1 个事件处理器 + 状态清理。
- 风险: 同 tick 多箭命中同一目标的竞态；弩（同样是 projectile）一并受影响。

#### 旋钮 N3 断电

- 动作: `InvincibleFrameEgregatorItem` 对 `IS_PROJECTILE` 直接 return；`Shadow` 的清零改为只对非投射物生效（额外伤害保留）。
- 结果: 弓只剩远距口径 ⇒ L4 **28.6**。要回到 86 只能抬单箭: `base_stats.projectile_damage +2.0` ⇒ 单箭 `ceil(10V)` = 12 / 16 / 22 / 32 ⇒ 四级 16.0 / 21.3 / 31.4 / 45.7, **仍不到 86**；要把 L4 推到 86 需单箭 60（`PDE +40`）, 显然不可行。⇒ **断电方案在 86 锚点下不可行。**
- 成本: 2 处 Java 判断。
- 风险: 多重射击彻底失去单体价值, 玩家会觉得这个 trait 是负收益。

### 4.5 旋钮对照

- 基准（保留清零点 + `N=3`）: L4 贴脸 **85.7** / 远距 28.6；改动量 0；多重射击价值完整；与裁定 2 契合。
- N1（`k=0.5` / `k=1`）: **65.2 / 52.4**；改动量约 40 行；多重射击价值完整；与裁定 2 契合。
- N2: 单体 **28.6**、多目标仍全额；改动量中等；多重射击只保留 AOE 价值。
- N3: 单体 **28.6** 且无法回到 86；改动量最小；多重射击价值基本丧失。

⇒ **结论: 基准口径即落地口径；N1 是唯一的「连续可调降档」旋钮, N2 / N3 在 86 锚点下不采用。** 这也与用户 m00786 的意图一致——要的是「毕业武器 ≈ 86」, 不是「把弓压回 52」。

## 五、弓侧 build：从「只有多重射击一条路」到两条互斥流派

### 5.1 三条成本线：槽位稀缺性只在中期成立

在给弓设计流派之前必须先确立一条纪律, 否则所有 build 都会撞上 86 锚点。

**先把一条会推翻常规判断的事实摆在前面：本整合包临近毕业时, 槽位不是稀缺资源。**

`kubejs/server_scripts/recipes/misc/tconstruct/Modifier.js` 覆盖了 TConstruct 原版的 slotless 配方, 且都**没有设置等级上限**（`ModifierRecipeBuilder.prototype.level(min, max)` 见该文件 174-185 行, 不调用就不写 `level` 字段）：

- `tconstruct:writable`（铭刻, :307-318）：每级 **+1 升级槽**, 材料 = 银板 + 可写书 + 天空尘；
- `tconstruct:draconic`（龙裔, :293-304）：每级 **+1 能力槽**, 材料 = 龙鳞 + 钛齿轮 / 钛板；
- 两者的修饰符本体定义在 `analysis/tcon_java/slimeknights/tconstruct/tools/data/ModifierProvider.java:289-296`：`writable` / `recapitated` / `harmonious` / `forecast` / `embossed` / `resurrected` = 每级 +1 **升级**槽（`ModifierSlotModule.slot(SlotType.UPGRADE).eachLevel(1)`）, `gilded` = 每级 +2 升级槽, **`draconic` = 每级 +1 能力槽**（`slot(SlotType.ABILITY).eachLevel(1)`）。

而 TConstruct 原版这几个配方都写了 `.setMaxLevel(1)`（`analysis/tcon_java/slimeknights/tconstruct/tools/data/ModifierRecipeProvider.java:353-364`）, 整合包覆盖时取消了这一限制 ⇒ **只要材料够, 槽位可以无限叠**。

> **结论：槽位经济只在中期成立, 毕业期是伪命题。** 所有「槽位不够所以装不下 / 靠槽位占用实现互斥 / 多个技能不能都装」的论证都必须作废（本文旧稿犯过这个错, 此处按实测代码修正）。

把弓可获得的每一份强度按成本重新分类, 仍然是三层, 但含义变了：

1. **材料层（免费, 选择即持有）**：弓臂与弓把的材料数值（VELOCITY / DRAW_SPEED / 耐久）与材料 trait（ranged 组的 multishot、shadow、ductile、lightweight 等）。换材料不需要任何额外物品 —— **这是唯一在结构上不可能「全都要」的成本, 因为一把长弓只有两个弓臂槽和一个弓把**；
2. **投入层（每次投入一份材料, 可无限次）**：占槽修饰符（converge / multishot / expanded / luck / unbreakable …）。因为槽位可无限购买, 它的真实成本是**材料 + 时间**, 不是槽位稀缺。它既可以给横向能力, 也可以给纵向加伤；
3. **消耗层（每次成本）**：箭矢本身。箭头材料决定 `ammo` 组的 trait（辉光石箭头 = keen 2 即 +1.0 projectile_damage）, 每射一发消耗一根。

**纪律因此改成两条, 且都不依赖槽位：**

- **纵向溢价的定价权在「材料价格」, 不在「槽位占用」。** 弓的基础射速 1.333~1.429 发/秒且每发 3 箭, 任何 +5% 的纵向加成在 3 箭全中时都会被放大 3 倍（DPS = 单箭 × R × 3）。若给弓一个便宜的「每级 +10% projectile_damage」升级, 2 级就能把 L4 从 85.7 推到 103 —— 拦住它的不可能是槽位（槽位买得到）, 只能是**这件修饰符的配方材料在毕业期仍然昂贵**（龙鳞、下界之星、Boss 掉落）。
- **消耗层是唯一「自动按使用量收费」的通道**, 因此纵向溢价的默认位置仍然是它：每发收一次成本, 打小怪心疼、打 Boss 舍得。这正是「毕业武器」该有的形态 —— 毕业不是「永久毕业」, 而是「有能力承担更高的边际成本」。

由此得到本章的强度天花板（与槽位多少无关）：

- 材料层（四级弓臂 + 弓把各挂 multishot 1）：**32.0 / 40.0 / 60.0 / 85.7**, 这就是锚点, 也是玩家「造完就能用」的强度；
- 投入层：**设计上限 124.3**（与近战强化件档 110~130 对齐）。可达性由**配方材料价格**决定, 不由槽位决定；
- 消耗层：辉光石箭头 keen 2 ⇒ 单箭从 20 变 29 ⇒ L4 从 85.7 到 **124.3**；这是唯一的纯纵向通道。

> **推论（后文多处引用）**：既然槽位可以买无限, **「互斥」就必须由机制语义实现, 而不是由槽位占用实现**。5.3 的 `point_blank` 与 `converge` 因此采用「代码层读等级互斥 + 效果互相抵消」的双保险（8.1 ③）。

### 5.2 流派 A｜收束齐射（Converged Volley）—— 单体远射型

**一句话**：用 `nebula_tinker:converge` 把 3 箭的水平散布压窄, 把「满伤圈」从 **1.70 格**拉到 **8.60 格**（4 级）。纯改距离、不改伤害。

**基准事实（本轮修正）**：TConstruct 原版 3 箭是**垂直**扇形（`ModifiableBowItem.java:242-243` 用 `living.getXRot() + angle`）, 但 Nebula 的 `ModifiableBowItemMixin`（`analysis/_nb_out/dev/celestiacraft/tinker/mixin/ModifiableBowItemMixin.java:23-41`）把整段 `shootFromRotation` 重定向成 `shootFromRotation(entity, living.getXRot(), living.getYRot() + direction, ...)`, **任何等级（包括 0 级即没装 converge）都走这条路径**。裸弓的缩放系数是 `(5-0)/5 = 1.0`, 于是它就是**水平 ±10°**。

⇒ 容差 = 目标半宽 **0.3**（僵尸宽 0.6）, 不是半高 0.95 ⇒ 三箭全中极限 = `0.3 / tan(10°) ≈ 1.70 格`。这就是旧稿「1.7 格断崖」的原始来源, 它是对的。

**等级曲线（按 `(5-L)/5` 缩放水平角度）**：

| converge 等级 | 散布角 | 三箭全中极限 | 相对裸弓 |
| --- | --- | --- | --- |
| 0（裸弓） | ±10° 水平 | **1.70 格** | 基准 |
| 1 | ±8° 水平 | 2.13 格 | +25% |
| 2 | ±6° 水平 | 2.85 格 | +68% |
| 3 | ±4° 水平 | 4.29 格 | +152% |
| 4 | ±2° 水平 | **8.60 格** | **+406%** |
| 5 及以上 | **±0°（完全沿准心）** | **∞（不受几何限制）** | 3 箭轨迹完全重合；满伤圈由瞄准精度决定（未采用, 见下） |

**两处必须先讲清的结论**：

1. **1~4 级全是正收益**（旧稿误判为「1~3 级对单体积负收益」, 那个判断建立在「基准是垂直扇形」之上；基准是水平, 所以不成立）。只是 1~3 级幅度小, 4 级是一次跳变。
2. **5 级是完全收敛, 不是降级**（按用户 m01480 修正）：`ModifiableBowItemMixin.java:31` 的条件是 `mainHandConvergeLevel <= 4 && offhandConvergeLevel <= 4`, 5 级走 `else` 分支 `arrow.m_37251_(entity, living.m_146909_(), yRot, roll, velocity, inaccuracy)` —— `xRot` 被换成**玩家视角本身**（丢弃传入的 `angle`）, 而传入的 `yRot` 在原版调用里就是 `living.getYRot()`（散布加在 `xRot` 上, `yRot` 本身无偏移）, 所以 **3 支箭全部沿准心射出、轨迹完全重合**；5 级以上（`getModifierLevel` 返回 6、7…）同样走这条分支, 行为与 5 级一致。
   ⇒ 满伤圈不再受几何限制, 只受「瞄得准不准」与箭速衰减限制。**这意味着 5 级 converge 等于取消距离分层**（L4 弓在任意距离都是 3 箭全中 85.7；100 格处箭速衰减约 9%, 仍有 78）, 与「梯度分化：远距离明显衰减」的口径直接冲突 ⇒ 本文把上限锁在 4 级（A0）, 把 5 级的完全收敛列为**未采用的设计**（D12）。

**落地动作（两个方案, 选一个）**：

- **A0（推荐, 零 Java 改动）**：把 `kubejs/server_scripts/recipes/misc/tconstruct/Modifier.js:332-342` 的 `level(1, 5)` 改成 `level(1, 4)`。曲线 1.70 / 2.13 / 2.85 / 4.29 / 8.60 单调递增, 5 级的完全收敛分支永远走不到 —— 锁 4 是**平衡闸门**（防止取消距离分层）, 不是修 bug。
- **A1（可选, 改 mixin 约 3 行）**：把 `(5 - L) / 5` 换成 `(6 - L) / 6` 再平方, 即 `float convergedResult = (6 - L) * (6 - L) / 36.0F;`, 曲线 2.47 / 3.86 / 6.87 / **15.5** 格 —— 起步更友好、4 级更强。代价是 4 级把满伤圈拉到 15.5 格, 需要在 Boss 战复测。

**为什么不改 mixin 的平面选择**：走到水平是**有意设计**（水平散布让玩家靠横向摆位覆盖并排目标, 垂直散布只能靠高度）。改回垂直等于给裸弓白送 3.2 倍容差（1.70 → 5.39 格）, 那是免费大加强, 与「削尖峰」的目标相反。

**箭速衰减核对**：初速 9.6 格/tick, 飞 8.6 格约 1 tick, 重力与阻力（每 tick ×0.99）带来的速度损失 <3% ⇒ 8.6 格处单箭仍是 19~20, 85.7 的名义值可用, 实测按 82~85 记。

**成本**：converge 占 `upgrades 1`（长弓 upgrades 2 位, 装完剩 1）；配方材料 `thermal:rf_coil + functionalstorage:redstone_upgrade`（`Modifier.js:332-342`）, 中期可量产。注意这个槽位占用**不构成任何限流**（5.1：升级槽可无限购买）, 它只是让玩家在中前期需要做一次取舍。

**强度对账**：1.7 格内 85.7（不变）；1.7~8.6 格从 28.6 拉回 85.7。它不改任何 DPS 数字, 只把「满伤区」从 1.7 格扩到 8.6 格 —— 这就是用户所说的 converge 提高泛用性。

### 5.3 流派 B｜贴身散射（Point-Blank Scatter）—— 6 格内的群伤型, 与齐射互斥

**一句话**：`cmi:point_blank` 让箭在 6 格内命中时炸开一片；单体不变（85.7）, 3 目标从 85.7 提到 **205.7**。近战侧对应的是重武器的溅射强化（劈刀 3 目标 139.4、6 目标 262.1）⇒ **3 目标弓更优、6 目标平手**。

**为什么这条流派必须存在**：齐射把弓的强区拉远（1.70 → 8.60 格）, 但弓的群伤始终被「每发 3 箭」钳死在 3 个目标、总输出 85.7。玩家贴身面对一群怪时, 弓反而是最差的选择。给弓一条「贴脸散射」的路线, 等于把「近身」与「远射」拆成两条各自的最优点：**齐射吃远, 散射吃近**, 玩家必须选一侧。

**机制（全部走 TConstruct 原生 hook, 不需要改 mixin）**：

- 载体 `cmi:point_blank`, 占 `upgrades 1`, level 1~3；
- hook：`projectileHitEntity`（`ProjectileHitModifierHook`, KubeJS 侧 `ModifierBuilder.projectileHitEntity(...)`）；
- 触发条件：命中点与**射手**的距离 ≤ **6 格**；
- 效果：以命中点为中心 **1.5 格**内最多 **2** 个其他生物, 各受 `比例 × 该次箭的直接伤害`, 结算走 `ToolAttackUtil.attackEntitySecondary`（无击退、不触发暴击、不触发任何技能层数）；
- 比例：L1 **40%** / L2 **55%** / L3 **70%**；
- 同一 tick 同一目标只吃**一次**箭爆（防止三箭落在同一点时重复叠加）。

**数值（L4 紫金臂 ×2：单箭 20、R = 1.429、3 箭/发）**：

| 目标数 | 直接伤害 | 箭爆 | 合计 |
| --- | --- | --- | --- |
| 1 | 85.7 | 0（没有「其他生物」） | **85.7** |
| 2 | 85.7 | 1 × 3 × 0.70 × 20 × 1.429 = 60.0 | **145.7** |
| 3 | 85.7 | 2 × 60.0 = 120.0 | **205.7** |
| 6 | 85.7 | 仍只有 2 个被波及（每箭上限 2） | **205.7（封顶）** |

⇒ L1 三目标 154.3（波及 1 个）、L2 179.9、L3 205.7。**单调, 且 6 目标封顶**——这是刻意的：m01984 后近战的群伤只由重武器提供（劈刀 3 目标 139.4 / 6 目标 262.1）, 弓在 3 目标上更高、6 目标持平, 两侧都不存在「单体强且群体最强」的配置。

**与齐射互斥的实现**：

- **槽位层（辅助, 不可依赖）**：两者与 `converge` 同占 `upgrades 1`, 长弓原生只有 2 个升级槽, 看起来能挤掉对方 —— 但 `tconstruct:writable` 每级 +1 升级槽且无等级上限（5.1）, **槽位层不构成任何保证**, 只能算心理提示；
- **代码层**（更可靠）：`point_blank` 的每个 hook 入口先读 `tool.getModifierLevel(new ResourceLocation("nebula_tinker", "converge"))`, `> 0` 则直接返回原值；`tooltipSetting` 同时把提示改成「与收束互斥, 当前失效」；
- **设计理由（写进 tooltip）**：收束把三箭压到几乎同一点, 三次箭爆会全砸在同一片 1.5 格区域, 被「同一 tick 只吃一次」吃掉两次 —— 不是人为限制, 是机制上互相抵消。

**代价清单（它不撞锚点的原因）**：

1. 单体满伤圈退回 **1.70 格**（装不了 converge）；
2. 只在 **6 格**内触发, 超出等于没装；
3. 占 `upgrades 1` 且与 `converge` 代码层互斥（槽位不是约束, 真正的约束是 8.1 ③ 的互斥判定）；
4. 箭爆不吃暴击、不吃任何按目标数追加的效果。

**配套强化（投入层, 横向）**：

- `cmi:scatter_lens`（散光镜, upgrades 1, level 1）：箭爆可波及 **3** 个目标 ⇒ 6 目标 = 85.7 + 3 × 60.0 = **265.7**, 与近战劈刀的 6 目标 262.1 基本持平；
- `tconstruct:lightweight`（attack_speed / draw_speed / velocity 同步 +0.03~0.08）：射速上去, 箭爆频率同步上去 ⇒ lightweight 2 时 R 1.538, 三目标 **221.4**。它属于「横向提速」, 上限仍在近战之下, 按 5.1 的纪律**允许**；
- 消耗层：光辉石箭头 `keen 2`（单箭 29）⇒ 三目标 = 124.3 + 2 × 3 × 0.70 × 29 × 1.429 = 124.3 + 174.0 = **298.3**（全投入上限, 每发付账）。

**为什么暗影钢不单独成流派（本轮裁定）**：`shadow` 的 +3 真实伤害要变成流派, 必须配一整套「虚空伤害」强化（按等级放大、穿透、与 zeroth 系材料联动）, 工作量远超其余四条近战技能, 收益却只是打硬目标的约 10% 溢价。因此**不做独立流派**：`shadow_steel` 的 `ranged: shadow 2` 保留为材料层的固有溢价（3 箭 +9, 约 +10%, 仍在 86 锚点 ±15% 的容差内）, 不给它单独的强化路线。

### 5.4 留档：两条不构成流派的路线

**留档 A｜疾速薄射（Rapid Draw）—— 手感型, 天然低于锚点**

定义：DRAW_SPEED 堆高、VELOCITY 压低, **DPS 守恒、把伤害从单发搬到射速**。若只加 DRAW_SPEED 不减 VELOCITY, L4 从 D 1.5 提到 1.9 就是 109 DPS, 直接撞锚点, 所以它必须是「换」而不是「加」。

当前材料池里**没有**「高 drawSpeed 低 velocity」的弓臂（见 2.4 的 limb 表）, 所以只能靠修饰符：`nebula_tinker:featherweight`（draw_speed +0.05/级、accuracy +0.05/级, 代价护甲 −0.625/级、移速 +5%）是唯一「加 draw_speed 不加 velocity」的现成件。featherweight 2 + 不锈钢臂 ×2 ⇒ 单箭 10、R 1.538 ⇒ **46.2 DPS**。
⇒ 它天然低于锚点, **不需要平衡干预**, 也不值得专门做内容。留档在此以免后人重复研究。

**留档 B｜弹种特化（Ammo Specialization）—— 消耗层通道, 不是流派**

数值链（已确证）：`baseDamage = 箭自身 PROJECTILE_DAMAGE − 2.0 + 弓的 PROJECTILE_DAMAGE`；普通箭与弓侧默认都是 2.0 ⇒ `baseDamage = 2.0` ⇒ L4 单箭 `ceil(9.6 × 2) = 20`。

`tconstruct:keen` 是 arrowHead 之外唯一能改箭 PDE 的现成通路（`stat_boost projectile_damage`, 每级 **+0.5**）。箭头挂 keen 2 ⇒ 箭 PDE 3.0 ⇒ `baseDamage = 3.0` ⇒ 单箭 `ceil(9.6 × 3) = 29`, **+45%**。TConMaterial.js:299-301 已经给 `refined_radiance`（光辉石）的 `ammo` 组挂了 `keen 2`, 也就是说现有配置下用光辉石箭头就能把 L4 从 85.7 打到 **124.3**, 但整合包里没有引导。

| 箭头材料 | ammo trait | 单箭（L4） | 每发 3 箭 DPS | 成本 |
| --- | --- | --- | --- | --- |
| 任意无 trait 材料 | — | 20 | 85.7 | 1 根普通箭 |
| 光辉石 | keen 2（+1.0 PDE） | 29 | 124.3 | 1 根光辉石箭 |
| 紫水晶 | crystalshot 1（不消耗箭矢类） | 20 | 85.7, 但省箭 | 1 根紫水晶箭, 可回收 |

## 六、近战侧：材料专有技能（Material-Exclusive Skill）

### 6.1 为什么技能必须挂在材料上, 而不是做成通用修饰符

这是本章与旧稿（「六个通用 build 流派」）的根本分歧, 先把它论证清楚。

**第一个理由：与弓对称。** 弓之所以「裸弓就能到 85.7」, 是因为 `multishot` 是 `ranged` 组的材料 trait——黄铜弓把挂 multishot 1、暗影钢弓把挂 shadow 2 + multishot 2（TConMaterial.js:212-213、271-273）。材料 trait **不占任何槽位**, 所以弓的「三条箭」是免费的。近战若要同档, 机制也必须是非占槽的, 否则两侧的成本结构不对等。

**第二个理由（按实测修正）：槽位在毕业期可以无限购买, 所以真正的稀缺资源是材料。**
`kubejs/server_scripts/recipes/misc/tconstruct/Modifier.js` 覆盖的 `tconstruct:writable`（:307-318）与 `tconstruct:draconic`（:293-304）都**没有设置等级上限**（不调用 `ModifierRecipeBuilder.level(min,max)`, 见该文件 174-185 行）, 而 TConstruct 原版给它们写了 `.setMaxLevel(1)`（`ModifierRecipeProvider.java:353-364`）；对照 `ModifierProvider.java:289-296` 可知 `writable` 每级 +1 升级槽、`draconic` 每级 +1 能力槽。⇒ **临近毕业时槽位可以无限购买, 槽位不是稀缺资源**（5.1 有完整实测）。
这直接否定了「用槽位稀缺来约束技能数量」的做法：若把多个专有技能做成占槽修饰符, 玩家的最优解不是「多选一流派」, 而是**全装** —— 因为槽位买得到、材料也买得到。多个技能一旦同时生效（精准突击 + 回声追加 + 溅射光爆 + 破防穿甲 + 处刑）, 倍率会互相乘起来, 剑的峰值会从 85 冲到几百, 「流派」这个概念直接消失。
而材料是**结构上无法通吃**的：一把剑只有 `small_blade` 一个主刃部件, 刃用什么材料就只能有一种。⇒ **把技能绑到材料上, 是唯一能保证「同一时刻只有一条流派生效」的机制**。这条理由与「槽位不够」无关, 反而与「槽位无限」互相印证。

**第三个理由：材料选择才该是流派的入口。** 把技能绑到材料上, 玩家的决策变成「我要玩回声连斩 → 去找暗影钢」。这条决策链上有采矿、熔炼、部件制作、槽位修饰符搭配四个层次, 每个层次都是一个可以重复游玩的选择；而「装一个修饰符」只有一个层次。整合包的体量需要前者。

**由此定下近战侧的三层结构与对应强度带**：

| 层 | 获取成本 | 内容 | 目标强度 |
| --- | --- | --- | --- |
| 第 1 层 材料技能 | 免费（材料固有, 不占槽） | 四个专有技能 + `cmi:heavy_edge` 基线 | **85~88（锚点）** |
| 第 2 层 投入强化 | 每件一份配方材料（槽位可无限买, 成本在材料） | 每个技能 2~3 个针对性修饰符 | **110~130（设计上限）** |
| 第 3 层 消耗品 | 每战成本 | **近战没有**（见下） | — |

**近战没有第 3 层, 所以第 2 层必须给纵向。** 弓的纵向通道在消耗层（5.5 的光辉石箭头, 85.7→124.3）, 投入层只给横向能力（converge 扩距离）。近战没有消耗品, 若投入层也只给横向, 近战就永远停在 86 而弓可以到 124。因此近战的强化件必须能吃出 **+50% 的纵向**（86 → 129）, 这个数字与弓的消耗层上限对齐。

这带来一个不利后果必须提前说清：**近战的 129 是「装完永久有效」, 弓的 124 是「每发都在花钱」**。同样的上限, 成本形态不同, 近战在长时间低强度战斗（刷怪、挖矿）里更划算, 弓在高强度短战斗（打 Boss）里更划算。这是刻意保留的生态位差异, 不是漏洞——但它意味着近战的上限不能给到 150, 必须卡在 130 以内, 否则「永久有效」的 150 会全面压过「每发付费」的 124。

**而且必须诚实说明：在无限槽位的前提下, 这个 130 是设计意图, 不是机制保证。** 因为 `tconstruct:writable` / `tconstruct:draconic` 让槽位可以无限购买（5.1）, 玩家理论上能把十五个强化件全装上。130 靠三条软约束守住：

1. **材料定价**（本文采用）—— 强化件配方在毕业期仍然昂贵（龙鳞、下界之星、Boss 掉落）, 把「再装一件」变成经济学问题；
2. **同类互斥（已裁定下沉到材料层, 见 6.2b）** —— 流派冲突从「选材料」这一步就开始：技能材只给 `head`、每把武器只认一种技能材, 再用物品标签把武器与工具分开；强化件层的 `validateTool` 互斥只作第二道保险（例如 `sunder` 与 `hammerfall` 不能共存）；
3. **数值饱和**（自然结果）—— 强化件都是同一个 stat 的 add, 第 3 件边际收益已 <3%。

按 m01817 的裁定, ② 的主体已经下沉到**材料层**（6.2b：技能材只给 `head`、技能唯一性检查、武器 / 工具标签分流）, `validateTool` 里的强化件互斥只保留为第二道保险（约 40 行）。① 仍按 8.2 的十五个强化件挂 Boss / 末地级材料落地, ③ 是自然结果。**D15 已结案**, 见第十一章。

### 6.2 材料—技能映射总表（按 m01817：全部改挂新材料）

近战五个技能各自绑到一个**新注册**的载体材料上, 每个载体**只提供 `head` 一个属性组**；远程两个技能分别是标枪的 `head` 载（钛）与弩的 `limb` 载（以太）：

| 载体材料 | tier | 技能 id | 挂载 stat 组 | 载体类型 | 最适配武器 | 单体目标 DPS |
| --- | --- | --- | --- | --- | --- | --- |
| 铬 `chromium` | 4 | `cmi:precision_strike` 精准突击 | `tconstruct:melee_harvest` | 单发型（`head` 攻击 6.4） | **剑、镰 scythe** | 剑 85.0（100% 判定）/ 镰 27.5 |
| 钨钢 `tungsten_steel` | 4 | `cmi:echo_slash` 回声连斩 | `tconstruct:melee_harvest` | **多段型（`head` 攻击 1.9）** | **镰 scythe、镰刀 kama、匕首、剑** | 剑 85.8 / 匕首 85.8 / 镰刀 71.5 / 镰 32.9 |
| 红钕 `scarlet_neodymium` | 4 | `cmi:glow_splash` 溅射强化 | `tconstruct:melee_harvest` | 单发型（`head` 攻击 6.4） | **重武器中自带生物 AOE 者：劈刀、镰** | 劈刀 57.1（3 目标 139）/ 镰 27.5（3 目标 68） |

**载体攻击力为什么分两档**：单发型（精准 / 溅射 / 破防）的收益来自「单击 × 倍率」, 所以 `head` 攻击按 tier4 顶格给（6.4~6.5 ⇒ 剑裸 25.0）；多段型（回声）的收益来自「5 段百分比追加」, 若单击也顶格, 剑会到 130（25.0 × 5.20）, 因此它故意把 `head` 攻击压到 1.9（剑裸 16.3 ⇒ ×5.20 = 85.0）。**这不是数值例外, 而是「单击流 vs 多段流」的流派差异**：回声剑的单击只有精准剑的约三分之一, 但每击会跳出 5 个数字。

**为什么可以只给 `head`**：`TinkerToolParts.java:133-140` 里 `pick_head` / `hammer_head` / `small_axe_head` / `broad_axe_head` / `small_blade` / `broad_blade` / `adze_head` / `large_plate` **全部**是 `HeadMaterialStats.ID`；`:149-150` 的 `tool_handle` / `tough_handle` 才是 `HandleMaterialStats.ID`。而 `TinkerStationPartSwapping.java:152` 用 `registry.getMaterialStats(material, part.getStatType()).isPresent()` 过滤材料 ⇒ **只给 `head` 的材料做不出手柄与绑定**。三条结构性后果：

1. 技能只能从「刃 / 锤头」进入工具, 且做不出弓臂（`limb`）、弓把（`grip`）、盔甲（`plating`）⇒ 不污染弓曲线与装备线；
2. 没有 `handle` 属性 ⇒ 无法通过柄把第二个技能带进同一把武器；
3. `head` 组同时服务采集工具（镐头也是 `head`）⇒ 仍需要武器 / 工具标签分流, 见 6.2b。

**为什么不再顺手用现有的暗影钢 / 紫金 / 耐热金属**：`shadow_steel` 的 `melee_harvest` 组现在挂着 `shadow 1`, 替换它就是 D10 的取舍；改用新载体后**暗影钢保留 `shadow 1`**（`ranged` 的 `shadow 2` 也不动）, **D10 自动消解**。同理, 紫金与耐热金属继续保留各自的 `insatiable` / `enhanced`, 不再承担技能载体。

**四个都挂在 `melee_harvest` 组**：该组 = `HeadMaterialStats` + `HandleMaterialStats` + `Binding`（`MaterialRegistry.java:105-107`）, 只服务近战 / 采集, 不污染 `ranged` 与 `armor`；现有文件里 `brass` 的 clockwork 2、`shadow_steel` 的 shadow 1、`stainless_steel` 的 ductile 2 都挂在这一组, 是既有惯例。

### 6.2b 材料层互斥与「武器材 / 工具材」分流（m01817 的落地）

**问题**：`head` 组同时服务刃、锤头、镐头与 `large_plate`；TCon 的材料 trait 又是按 stat 组分发的（`MaterialStatsModule.java:186` 对每个部件都 `getTraits(material, statTypeGroup)`）。因此「只给 `head`」并不能自动区分武器与工具, 也挡不住「劈刀用两种技能材做出两个技能」——劈刀 = `broad_blade` + `large_plate`, 锤 = `hammer_head` + `large_plate ×2`, **这些部件全是 `head` 类**。

**三族材料**

- **武器材**：铬 / 钨钢 / 红钕 / 铂（备选 钒 / 钛 / 淤钢 / 铝合金）
  - 只给 `head`；`miningSpeed` 压到 **5.0~6.5**；挂战斗技能；
  - 材料标签进 `data/tconstruct/tinkering/tags/materials/melee_harvest/melee.json`（`TinkerTags.java:605` 的 `MATERIALS.MELEE`）
- **工具材**：从 钛 `titanium` / 钒 `vanadium` / 淤钢 `siltsteel` / 铝合金 `aluminum_alloy` 里选 3 个
  - 给 `head` + `handle` + `binding`；`miningSpeed` **8.0~9.0**、耐久 1500~2000、`melee_attack` 4.0~4.5；
  - 挂采集向 trait（`tconstruct:haste`、`nebula_tinker:petramor`, 或新建 `cmi:deep_dig`）, **不挂战斗技能**；
  - 材料标签进 `.../melee_harvest/harvest.json`（`TinkerTags.java:606`）
- **通用材**：现有 tier2~4 全部保持原样, 留在 `general.json`（`TinkerTags.java:604`）

**三层闸门（代码层）**

1. **武器 / 工具分流**：五个近战技能第一行 `if (!isWeapon(tool) || context.isProjectile()) return base;`, 用物品标签 `#tconstruct:modifiable/melee/weapon`（`TinkerTags.java:258` 的 `MELEE_WEAPON`, 其 values = `#modifiable/melee/primary` + `/sword` + `/parry`）；工具走 `#tconstruct:modifiable/harvest`（`:263`）。
2. **材料唯一性**：技能 hook 入口检查工具上是否同时存在另一种技能载体材料 / 另一种技能 modifier —— 若是, 本技能返回原值（两者互斥、等于双输）。这样「劈刀用两种技能材」不会变成双技能, 只会变成双失效（tooltip 必须写明原因）。
3. **武器类型细分**：沿用 6.7 的各技能过滤（`ATTACK_SPEED`、是否自带 AOE 等）。

**结论**：材料决定流派, 标签决定生效面, 唯一性检查兜底 ⇒ 流派冲突在「选材料」这一步就已经发生, 而不是等到装槽位强化件时才发生。

### 6.3 技能一｜精准突击（Precision Strike）—— 载体：铬

**一句话**：只要你在「攻击冷却刚好的那个瞬间」打出这一击, 这一击的伤害直接乘一个固定倍率；没有层数、没有爬坡、不留缓存（对应怪物猎人片手剑的「精准突击」, 用户 m01859）。

**机制**：

```
C     = ceil(20 / attackSpeed)            // attackSpeed 取玩家 ATTACK_SPEED 属性实时值
J     = max(3, ceil(C * 0.25))            // 容差窗口（剑 C=14 ⇒ J=4）
gap   = t_now - t_prev                    // 距上次命中的 tick 数
gap ∈ [C, C+J]  ⇒ 本次伤害 × M            // 判定达成
gap < C 或 gap > C+J ⇒ 本次伤害 × 1.0     // 判定失败, 不惩罚
M     = 1.4 + 0.5 × level                 // L1 1.9 / L2 2.4 / L3 2.9 / L4 3.4
```

材料挂 **level 4** ⇒ `M = 3.40` ⇒ 剑 **85.0 DPS**。

**与旧稿（10 层叠乘）的区别**：数值上限完全一样（都是 ×3.40、85.0）, 但旧稿要「连准 10 次才到 85」, 中途被打断就归零；新机制是「每一次都在赌判定」, 判定成功立刻见效。**因此 6.4~6.6 的倍率与目标 DPS 全部不用重算。**

**达成率与期望**：

| 达成率 | 等效倍率 | 剑 DPS | 说明 |
| --- | --- | --- | --- |
| 100%（冷却一好就点） | ×3.40 | **85.0** | `gap = C` 必定落在窗口内 |
| 80% | ×2.92 | 73.0 | 有 1/5 的攻击点早或拖沓 |
| 60% | ×2.44 | 61.0 | 连点 + 拖沓混合 |

⇒ 这是本流派唯一的「操作税」：**判定失误不会倒退, 只是白打**。点太早（`gap < C`）还要额外吃 `ToolAttackUtil` 的冷却衰减（`0.2 + cooldown² × 0.8`, 最低两成）。

**为什么这个机制适配「冷却适中」的武器（m01984）**：冷却 `C` 由攻速决定 ⇒ 匕首 C=11、剑 C=14、镰 C=29、战斧 C=34；判定窗宽 `J = max(3, ceil(C × 0.25))` 随冷却等比放大, 所以窗口的**相对占比**在所有武器上接近（约 25% + 3t）, 差别只在「单位时间的机会数」与「单次容错时间」的取舍。剑（C=14、J=4）与镰（C=29、J=8）正好落在「机会够多、容错也够宽」的中间档, 这是把它们定为本命的原因；匕首机会最多但每次只有 3 tick, 战斧容错宽但机会太少。

**武器类型过滤**：`attackSpeed >= 0.6` 且属于 `#tconstruct:modifiable/melee/weapon`（剑 1.45、镰 0.70 都在窗内）。**原稿的 `>= 1.2` 门槛必须下调**——它会把用户指定为本命的镰（0.70）排除在外；代价是战斧（0.60）也满足下限, 但它的判定机会最少、不推荐。过滤在代码里判, 不写在文档里指望玩家自觉。

**针对性强化（投入层）**：

| 强化 | 槽位 | 等级 | 效果 | 配方要点 |
| --- | --- | --- | --- | --- |
| `cmi:tempo_window` 节拍窗 | upgrades 1 | 1~2 | 容差 J **+1 tick/级**（提高达成率, 不提高上限） | 精密构件 + 红石中继器 |
| `cmi:precision_edge` 精锋 | abilities 1 | 1 | 判定达成时倍率再 **×1.15** ⇒ 剑 97.8 | 铬锭 + 龙息 |
| `cmi:step_in` 进身 | upgrades 1 | 1 | 判定达成时返还 **2 tick** 攻击冷却 ⇒ 剑约 92 | 精密构件 + 幽匿感测体 |
| `tconstruct:swiftstrike`（原生） | upgrades 1 | 1~5 | attack_speed **+5%/级** ⇒ C 缩短、判定更密 | 原版已有 |

**互斥**：

- 与 `nebula_tinker:killing_rhythm`（杀戮节奏）**必须互斥**, 否则节奏类增益叠乘会让剑到 160+；
- 与 `nebula_tinker:clockwork`（发条, 有速度效果时加暴击）可共存, 但需把 clockwork 的加成改成只加概率不加倍率；
- 与 `nebula_tinker:acupoint`（死穴, 血量斩）**必须互斥**——97.8 的一击若触发血量斩, 等于无条件斩杀半血怪。

### 6.4 技能二｜回声连斩（Echo Slash）—— 载体：钨钢

**一句话**：一次挥击之后, 伤害会在 4/8/12/16/20 tick 各延迟追加一段, 像回响一样。

**为什么适配剑 / 镰 / 镰刀 / 匕首（m01984）**：追加段按**本次伤害的百分比**结算, 所以「低单击 + 高攻速」的武器天然吃亏, 机制里因此加了 floor 下限保护。这让匕首（钨钢刃单击 6.4、as 1.85）与镰刀（4.7、as 1.60）第一次能被托到锚点附近, 而剑（11.2、as 1.45）靠百分比本身就够。镰（单击 7.0、as 0.70）是四者里最弱的, 仍留在缺口区（见 D2）。设计对应 MH 太刀的「樱花斩」：一次挥击、多段延迟结算。

**机制**：

```
命中后依次排 5 个延迟任务（4/8/12/16/20 tick）
每段伤害 = max(本次伤害 × 段比例, 8)         // floor 8, 保护低基础武器
段比例 = 80% / 80% / 80% / 80% / 100%      // 合计 +420%
每段走 ToolAttackUtil.hurtNoInvulnerableTime（官方无 i-frame 入口, :336-347）
每段不产生击退、不触发暴击、不触发其他技能的层数、不触发血量斩类效果
```

**数值（钨钢刃, floor 8）**：

| 武器 | 钨钢刃裸 DPS | 单击 | 每段取值 | 结果 |
| --- | --- | --- | --- | --- |
| 剑 | 16.3 | 11.2 | 0.8 × 11.2 = 9.0 > 8 ⇒ 按百分比 | **85.8** ✓ |
| 匕首 | 11.8 | 6.4 | 0.8 × 6.4 = 5.1 < 8 ⇒ 取 8 | **85.8** ✓（floor 托底） |
| 镰刀 kama | 7.5 | 4.7 | 3.8 < 8 ⇒ 取 8 | 71.5（83% 锚点） |
| 镰 scythe | 4.9 | 7.0 | 5.6 < 8 ⇒ 取 8 | 25.5（3 目标 76.5；按 AOE 档验收, D2 结案） |

**为什么是 5 段而不是 4 段**：4 段（65/65/65/50 = +245% ⇒ ×3.45）只能把钨钢剑推到 56.9, 差 86 还有 33%；6 段会把剑推到 100 以上, 匕首与镰刀则被 floor 放大到 100 上下。5 段是让「剑 85.8 / 匕首 85.8 / 镰刀 71.5」都落在锚点附近的唯一整数解。

**floor 取值：8 点。** 理由：8 点刚好能砍穿僵尸级护甲让数字可见（4 点会被护甲吃掉）；上限由「匕首与镰刀必须落在锚点」反解——floor 10 会让匕首（钨钢刃单击 6.4、as 1.85）拿到 5 × 10 = 50 的固定追加, 被攻速放大后到 104（超锚点 21%）；floor 8 时匕首正好 85.8、镰刀 71.5。**floor 是「低基础武器的保护」, 不是「所有人都能拿的保底」**：剑的百分比本来就高于 8, 碰不到它。

**暗影钢恢复独立（D10 结案：走新材料路线）**：回声连斩改挂新注册的钨钢, `shadow_steel` 的 `melee_harvest` 组**继续保留 `shadow 1`**, `ranged` 的 `shadow 2` 也不动（按 m01339 的裁定, 暗影不做独立弓流派, 它只作为暗影钢在弓上的固有溢价：3 箭各 +3 ≈ +10%, 仍在 86 锚点的 ±15% 容差内）。钨钢的 `head` 攻击按「多段型」给 **1.9**, 剑裸值约 16.3（刻意低于暗影钢 4.3 的裸值）, 因此本节 85.8 / 85.8 / 25.5 三个数成立（kama 的 71.5 仅作参考, 它不在十件名单内）。

**针对性强化（投入层）**：

| 强化 | 槽位 | 等级 | 效果 | 配方要点 |
| --- | --- | --- | --- | --- |
| `cmi:echo_lance` 回响枪 | abilities 1 | 1~2 | 段数 **+1/级**（每段 80%） | 钨钢板 + 回声碎片 |
| `cmi:echo_delay` 迟响 | upgrades 1 | 1 | 段间隔 **−1 tick**（伤害更早到账） | 石英 + 幽匿感测体 |
| `nebula_tinker:death_echo` 生命回响（原生） | abilities 1 | 1~3 | 低血量时暴击倍率提升 | 已有配方 |

装 `echo_lance 2` ⇒ 7 段（+580%）⇒ ×6.8 ⇒ 剑 **112.2**；再装 `death_echo 3` 打残血目标可到 130 上下。

**互斥**：与 `acupoint` 死穴**必须互斥**——回声的延迟段若触发血量斩, 会在 20 tick 内把目标从满血砍到 1 血, 且玩家无法中断。这是旧稿 R2 已经指出的秒杀链, 必须在代码层禁用（延迟段不触发血量阈值类效果）, 不能只写在文档里。

### 6.5 技能三｜溅射强化（Glow Splash）—— 载体：红钕

**这一步是对旧稿的翻转, 先说清楚错在哪。** 旧稿的 5.3「范围压制」是「给**不自带 AOE** 的武器新增一圈溅射」, 理由是「AOE 是近战唯一能超弓的生态位」。这个方向是错的：TCon 已经给了 4 把武器生物 AOE（`sword` 的 sweep_melee range 1.0、`cleaver` 的 sweep_melee range 2.0、`scythe` 的 circle_melee diameter 2.0、`kama` 的 circle_melee diameter 1.0）, 再给剑新增一圈溅射等于**在同一把武器上叠两层 AOE**, 而在没有 AOE 的锤、斧上新增溅射又违反了武器设计意图（锤斧的 AOE 是方块 AOE, 不是生物 AOE）。用户 m01056 的裁定「用于已有 AOE 的武器」正是这个意思：**溅射强化的作用对象是「已经会溅射的武器」, 它强化的是溅射本身。** 用户 m01984 又把它进一步收敛到**重武器**：四把生物 AOE 武器里, 剑（`sweep_melee 1.0`）与镰刀（`circle_melee 1.0`）属轻武器, 归给精准突击 / 回声连斩；溅射只落**劈刀（`sweep_melee 2.0`）与镰（`circle_melee 2.0`）**。大锤与板斧虽也是重武器, 但它们只有方块 AOE（`box_aoe`）, 对生物无群体收益, 因此不进本流派。

**TCon 的两套生物 AOE 必须先分清**（这决定了强化件能怎么加）：

| 模块 | 谁在用 | 结算方式 | 是否吃近战 hook | 触发条件 |
| --- | --- | --- | --- | --- |
| `sweep_melee` | 剑（range 1.0）、劈刀（range 2.0） | 直接 `aoeTarget.hurt(source, sweepDamage)` | **不吃**（不走 performAttack） | 极严：满蓄力、非冲刺、非暴击、非弹射物、在地面、移动速度低于移速 |
| `circle_melee` | 镰（diameter 2.0）、镰刀（diameter 1.0） | 对每个目标 `performAttack(tool, context.withAOETarget())` | **全吃**（每个 AOE 目标完整走一遍近战结算） | 仅 `!context.isExtraAttack()` |

⇒ **关键事实：剑和劈刀的横扫在默认状态下几乎没用**。`SweepWeaponAttack.getSweepingDamage` 读 volatile `tconstruct:sweep_percent`：>1.0 时取 100%, 0<p≤1 时取 `min(baseDamage, p×baseDamage+1)`, **p=0 时只有 1.0 点伤害**。而 `sweep_percent` 只由 `tconstruct:sweeping_edge` 修饰符提供（每级 +0.25, `sweeping_edge.json`）——也就是说**没有装 sweeping_edge 的剑, 横扫只掉 1 点血**。旧稿把剑当成「自带有效 AOE」是错的前提。

**机制**：

```
命中主目标后 6 tick, 结算一次「光爆」：
  半径 2.5 格内最多 8 个其他生物, 各受 本次伤害 × 240%（走 attackEntitySecondary, 无击退）
  主目标额外受 本次伤害 × 240%（回灌）
  每波及 1 个其他生物, 主目标回灌再 +5%（上限 +20%）
光爆段不触发其他技能（不吃精准突击判定、不吃回声延迟、不吃破防）
若武器自带 sweep_melee / circle_melee：自带段照常结算, 光爆是额外一层（不替代）
若武器不带任何生物 AOE 模块：光爆照常生效（因为红钕刃的任何武器都能触发）
```

**单体为什么不达 86（m01984 之后）**：回灌段是「无条件给主目标的 240%」, 所以即使周围一个怪都没有, 主目标也吃 `100% + 240% = 340%` ⇒ ×3.40 ⇒ 劈刀 16.8 → **57.1**、镰 8.1 → **27.5**。旧稿让红钕剑拿 25.0 × 3.40 = 85.0, 本质是「把 AOE 技能装在单体型武器上」凑出来的达标；m01984 把溅射限定到重武器后单体必然低于 86 —— 这是刻意的：**溅射流的验收锚点是群体（3 目标 139 / 67）, 单体只作副产品**（见 D4）。

**数值（红钕刃）**：

| 场景 | 劈刀主目标 | 劈刀副目标 | 劈刀合计 | 镰合计 |
| --- | --- | --- | --- | --- |
| 1 个目标 | ×3.40 = 57.1 | — | **57.1** | 27.5 |
| 2 个目标 | ×3.45 = 58.0 | ×2.40 = 40.3 | 98.3 | 47.0 |
| 3 个目标 | ×3.50 = 58.8 | ×2.40 ×2 = 80.6 | **139.4** | 67.3 |
| 6 个目标 | ×3.60 = 60.5 | ×2.40 ×5 = 201.6 | 262.1 | 126.4 |

⇒ 群体 3 目标 **139.4**（劈刀）超过弓 L4 的 85.7 且比单体高一档；6 目标 262.1 是弓的 3 倍, 因为弓被「一发 3 箭」钳死、近战 AOE 无上限 —— **这是刻意的**：溅射流的生态位是清杂。风险从「红钕剑一字堂」降级为「劈刀 / 镰 两把重武器在群怪场景占优」, 压力比旧稿小得多（剑已被移出本流派）, 对策见 9.2 的 R3。

**针对性强化（投入层）**：

| 强化 | 槽位 | 等级 | 效果 | 配方要点 |
| --- | --- | --- | --- | --- |
| `tconstruct:expanded` 延展（原生） | abilities 1 | 1~N | AOE 范围 +1/级（两条 WeaponAttack 都读 volatile EXPANDED） | `Modifier.js:464-476` 已注册 |
| `cmi:splash_focus` 焦光 | upgrades 1 | 1~2 | 主目标回灌 **+40%/级**（240%→320%） | 红钕锭 + 荧石 |
| `cmi:quake_core` 震核 | abilities 1 | 1 | 波及 ≥3 个目标时额外触发一次 100% 范围伤害 | 红钕锭 + 重核 |
| `tconstruct:sweeping_edge`（原生, 仅剑/劈刀） | upgrades 1 | 1~4 | 自带横扫从 1.0 点提升到 25%~100% | 原版已有 |

装 `splash_focus 2` ⇒ 回灌 320% ⇒ 主目标 ×4.20 ⇒ 劈刀 **70.6**（3 目标 151.2）、镰 **34.0**（3 目标 72.9）；再装 `quake_core` ⇒ 群体场景 +100% 一跳。

**`expanded` 是本方案的关键现成件**：它是「扩展 AOE 范围」的唯一通用入口, 且两条 WeaponAttack 都用 `ranges.compute(volatile EXPANDED)` 读它 ⇒ **对没有 AOE 模块的武器无副作用**（天然只对自带 AOE 的武器生效）, 零判定逻辑。这正是「溅射强化只给已有 AOE 武器」在实现层最省事的落点。

**互斥**：与 `acupoint`（死穴）互斥——光爆的 240% 段若触发血量斩, 等于范围斩杀。与 `killing_rhythm`（杀戮节奏）不冲突但需注意群体击杀会快速叠层。

### 6.6 技能四｜破防重击（Guard Break）—— 载体：铂

**一句话**：每第 2 次命中重击一次, 追加 500% 穿甲伤害, 并让目标陷入 5 秒「破防」（受到的所有伤害 +20%）。

**为什么是「第 2 次」而不是「第 3 次」**：破防重击的受众是大锤（as 0.75）、劈刀（0.85）、板斧（0.60）这类慢速重武器。若要求第 3 次命中, 单次要追加 1000% 才能把平均拉到 ×3.5——而 1000% 意味着单击出现 170+ 的数字, 视觉上像 Bug。**提高频率、降低单次**是让「重击」既可读又不破坏数字观感的唯一办法。

**为什么适配重武器（m01984）**：破防是**给团队吃的增益**（目标受伤 +20% 对所有来源生效）, 而「重击」这个名字本身就指向重武器。单人时它的收益不如回声连斩（×3.5 vs ×5.2）, 但队伍里每多一个人就在 20% 上再多分一份 —— 这是八个技能里唯一的团队向设计。**大锤与板斧只有方块 AOE, 对生物没有群体收益**, 所以它们的破防档就是纯单体 57.2 / 67.9；劈刀自带 `sweep_melee 2.0`, 是三个里唯一能与群体联动的。

**机制**：

```
计数 key = (玩家, 目标)；同一把武器命中同一目标时累计, 切目标清零
每第 2 次命中：
  追加 = 本次伤害 × 500% × (0.9 / attackSpeed)   // 按攻速缩放（m02098 裁定 4）
     ⇒ 板斧 750% / 劈刀 529% / 大锤 600%
  （hurtNoInvulnerableTime + damageSources().generic(), 穿甲）
  给目标挂「破防」：受到的伤害 ×1.20, 持续 100 tick, 只刷新不叠加
冷却：破防的重击追加不触发暴击, 也不吃精准突击/回声连斩的追加
```

**数值（铂刃）**：

| 武器 | 裸 DPS（含 F0） | 平均倍率 | 单体结果 | 群体结果 |
| --- | --- | --- | --- | --- |
| 板斧 `broad_axe` | 14.3（as 0.60） | 追加 750% ⇒ **×4.75** | **67.9** | 无（`conditional_aoe` 是方块 AOE, 对生物无效） |
| 劈刀 `cleaver` | 16.8（as 0.85） | 追加 529% ⇒ **×3.65** | **61.3** | `sweep_melee 2.0`, 需装 `sweeping_edge` 才有实质横扫伤害 |
| 大锤 `sledge_hammer` | 14.3（as 0.75） | 追加 600% ⇒ **×4.00** | **57.2** | 无（同上） |
| 矿锤 | 14.4（as 0.85） | ×3.65 | 52.6 | 无；技能照常生效, 不在十件名单内 |

⇒ 按攻速缩放后重武器单体 **57.2~67.9**, 是 86 锚点的 **0.67~0.79 倍**（m02098 裁定 4 直接修补了旧稿 0.58 倍的问题）。若不走缩放（一律 500%）, 会掉回 50.1~58.8、跌破团队档 55~70 的下沿。**破防的兑换币仍是「团队受伤 +20%」与「劈刀 3 目标 139.4」**, 剩余缺口列入 D18。

**针对性强化（投入层）**：

| 强化 | 槽位 | 等级 | 效果 | 配方要点 |
| --- | --- | --- | --- | --- |
| `cmi:sunder` 崩解 | upgrades 1 | 1~2 | 破防幅度 **+10%/级**（20%→40%） | 铂锭 + 炽铁 |
| `cmi:hammerfall` 落锤 | abilities 1 | 1 | 改为**每次命中**都触发, 但追加降到 200%（更平滑, 专为锤） | 铂锭 + 重核 |
| `tconstruct:smite` 斩魔（原生） | abilities 1 | 1~2 | 对亡灵额外加成 | 原版已有 |

装 `sunder 2` ⇒ 破防 40% ⇒ 团队总输出 +33%（按 3 人队计）；劈刀自身 61.3 不变（破防只影响后续命中）。

**互斥**：与 `acupoint`（死穴）互斥（同 6.4 的理由）；与 `capture_king`（擒王）可共存——擒王对高血量目标增伤, 与破防是两条独立乘算。

### 6.7 技能的过滤：三层闸门（必须有, 不能只写在文档里）

五个近战技能都挂在 `melee_harvest` 组（两个远程技能分别挂 `melee_harvest` 与 `ranged`）, 而该组也覆盖镐、斧、锄等采集工具, 且 `head` 类部件同时服务刃、锤头与 `large_plate`。因此每个技能在实现时必须自带三层判定：

**第 1 层 · 武器 / 工具分流**

| 判定 | 依据 | 效果 |
| --- | --- | --- |
| 是武器 | 物品标签 `#tconstruct:modifiable/melee/weapon`（`TinkerTags.java:258`, values = `#modifiable/melee/primary` + `/sword` + `/parry`） | 采集工具永不触发战斗技能 |
| 是工具 | `#tconstruct:modifiable/harvest`（`TinkerTags.java:263`） | 工具材的采集技能只在这一侧生效 |

**第 2 层 · 材料唯一性（6.2b）**

- 技能 hook 入口检查：若工具上同时存在另一种技能载体材料 / 另一种技能 modifier ⇒ 本技能返回原值
- 作用对象是劈刀（`broad_blade` + `large_plate`）与锤（`hammer_head` + `large_plate ×2`）——它们的两个部件都是 `head` 类, 只靠「只给 `head`」挡不住

**第 3 层 · 武器类型细分**

| 技能 | 生效条件 |
| --- | --- |
| 精准突击 | `ATTACK_SPEED >= 0.6` 且是武器（剑 1.45 / 镰 0.70） |
| 回声连斩 | 非纯采集的近战武器, 不设攻速门槛（镰 0.70 / 镰刀 1.60 / 匕首 1.85 / 剑 1.45） |
| 溅射强化 | 必须自带生物 AOE（`sweep_melee` / `circle_melee`）, 且按 m01984 只落重武器（劈刀 / 镰） |
| 破防重击 | `ATTACK_SPEED <= 1.0`（大锤 0.75 / 劈刀 0.85 / 板斧 0.60） |
| 处刑 | `0.8 <= ATTACK_SPEED <= 1.0`（短柄斧 0.90）；且 `!context.isProjectile()` |
| 投掷穿刺 | 仅 `context.isProjectile()` 为真（标枪投掷）；近战攻击不触发 |
| 装填齐射 | 仅弩：要求 persistentData 存在 `tconstruct:crossbow_ammo`（长弓天然没有） |

### 6.8 武器—技能适配矩阵（tier4, 不暴击口径）

下表是「材料做刃 + 只装技能、不装任何投入强化」的基础档, 按 m02098 的十件武器与三档验收（单体 85.7 / AOE 3 目标 85.7 / 团队 55~70）核对：

| 武器 | 裸 DPS（含 F0） | 适配技能 | 基础档 DPS | 最强投入档 | 备注 |

### 6.8b 三个补充技能：处刑 / 投掷穿刺 / 装填齐射（m02098）

**共同前提**：三个技能同样**挂在材料上**（不占槽位）；低基础补偿一律「按攻速缩放」, 不通胀攻击力。它们是 m02098 名单扩到十件后新增的三条路径。

**① 处刑 `cmi:execution`（载体：钒 `vanadium`, `head` 攻击 6.5）**

- **适配**：短柄斧 `hand_axe`（`ATTACK_SPEED = 0.90`）；过滤 `0.8 ≤ ATTACK_SPEED ≤ 1.0` 且 `!context.isProjectile()`
- **机制**：计数 key =（玩家, 目标）, **每第 2 次**命中追加 `900% × (0.9 / attackSpeed)`, 走 `ToolAttackUtil.hurtNoInvulnerableTime` + `damageSources().generic()`；追加段不暴击、不触发其他技能层数
- **数值**：短柄斧裸 14.9（单击 16.6 / as 0.90）⇒ 追加 900% ⇒ 平均 **×5.50** ⇒ **82.0**
- **强化件**：`cmi:execution_edge`（`upgrades 1`, 追加 +10%/级 ⇒ 1100%）、`cmi:merciless`（`abilities 1`, 目标血量 < 50% 时追加 ×1.5 ⇒ 92）
- **与破防的分工**：处刑是**单体**向（纯倍率、无状态、无团队增益）, 破防是**团队**向（破防 +20%）

**② 投掷穿刺 `cmi:impale`（载体：钛 `titanium`, `head` 攻击 6.5）**

- **适配**：标枪 `javelin`（parts = `small_blade` + `tool_handle` + `bow_limb` + `bow_grip`）；只在 `context.isProjectile()` 为真时生效
- **机制**：投掷命中追加 **85%** 穿甲（`hurtNoInvulnerableTime`）, 并**贯穿** —— 沿飞行方向 2 格内最多 2 个后续目标各吃 **60%**；追加段不暴击、不触发层数
- **数值**：`ATTACK_DAMAGE = (3.0 + 6.5 + 3.0 + 3.5) × 1.30 + 1.0 = 21.8`（含 `cmi:heavy_edge` 2 级与弓把 `melee_damage 3.5`）；`VELOCITY = 1 + 1.1 = 2.1` ⇒ 单发 **45.8**；`drawtime = ceil(20 / (1.25 × 0.935)) = 18t` ⇒ 1.11 发/秒；含回收实战 0.9~1.0 发/秒 ⇒ 裸 **41~46**；技能后单体 `45.8 × 1.85 = 84.7`, 贯穿 3 目标 **139.7**
- **强化件**：`tconstruct:returning`（原生, 投出后自动返回 ⇒ 射速稳定 1.11）、`cmi:pierce_lens`（`upgrades 1`, 贯穿目标 2 → 3）
- **与近战的隔离**：投掷间隔 18t 小于精准突击判定窗的下界 `C = ceil(20 / 0.935) = 22t` ⇒ 标枪投掷**天然吃不到精准突击**；同时五个近战技能都必须显式排除 `context.isProjectile()`, 否则投掷会打到 `onAfterMeleeHit`

**③ 装填齐射 `cmi:volley`（载体：以太 `etrium`, 挂 `tconstruct:ranged` 组的 `limb`）**

- **适配**：弩 `crossbow`（parts 只有 **1 根** `bow_limb`）；判定 = persistentData 里有 `tconstruct:crossbow_ammo`
- **机制**：装填完成后的**下一次齐射**, 每支箭伤害 **×2.1**, 发射后清除
- **数值**：`VELOCITY = 1 + 1.1 = 2.1` ⇒ 单箭 13；`DRAW_SPEED = 1.25` ⇒ 装填 16t + 发射 3t = 19t ⇒ **1.05 发/秒**；N = 3 ⇒ 裸 **41.0**；技能后 **86.1**（不含暴击；弩每支无条件暴击, 含暴击期望 ×1.25）
- **强化件**：`cmi:quick_load`（`upgrades 1`, `DRAW_SPEED +0.1/级`）、`cmi:volley_core`（`abilities 1`, ×2.1 → ×2.6 ⇒ **106.7**）
- **备选弓臂**：以太臂 `limb(0.15, 0.35, 900, 0.55)` ⇒ 单箭 10、D 1.70、周期 15t ⇒ 1.33 发/秒、裸 39.9、技能后 **83.8**（装填手感更顺, 单发更低）
- **为什么长弓吃不到**：长弓没有 `tconstruct:crossbow_ammo` 这个 NBT（装填只发生在 `ModifiableCrossbowItem.m_5551_`）, 判定天然失败, **不需要额外的武器类型过滤**

### 6.9 未采用的两个旧方案（留档以免重复研究）

**节奏爆发（Momentum, 未采用）**：原设计是「击杀叠势, 5 层后伤害 ×2.60、攻速 ×1.50」。未采用的原因：① 它与 Nebula 现有 `killing_rhythm`（杀戮节奏）在触发量（击杀）、维持方式（限时）上完全重叠, 玩家无法区分是哪个在生效；② 攻速 ×1.50 会把剑从 1.45 推到 2.17, 而 `ToolAttackUtil.java:260-264` 用 `round(20/attack_speed)` 把目标无敌帧压到与攻击间隔同量级, 攻速超过 2.0 后这个对齐会失效, 出现「打了没伤害」的怪现象；③ 它是「滚雪球」型, 在刷怪塔里会无限层叠。**结论：不新增, 把击杀向的收益留给 `killing_rhythm`。**

**纯数值路线（只加 attack_damage, 未采用）**：要把 tier4 剑从 25.0 推到 86, 需要 `cmi:heavy_edge`（每级 +1.5 attack_damage）约 29 级——单击会到 60, 僵尸（20 血）、末影人（40 血）一刀必死, 玩法变二值。而且 `heavy_edge` 是材料 trait, 挂 head 会同时影响该材料做的镐、斧、镰, 无法只给重武器。**结论：`heavy_edge` 只保留 2 级（+3.0）作基线, 纯数值路线现实上限 4~5 级（32~34）, 仅作零机制兜底与调参旋钮。**

### 7.2 距离口径（按 Nebula mixin 无条件换水平后的水平扇形重算）

**判定式**：3 箭在距离 d 处的横向偏移 = d × tan(半角), 半角 = 10° × (5 − L)/5（L = converge 等级；(5 − L)/5 即 `ModifiableBowItemMixin.java:23-42` 的缩放系数）。容差 = 目标半宽（僵尸 0.3）。**此式只适用于 0~4 级**：mixin 的 `if (mainHandConvergeLevel <= 4 && offhandConvergeLevel <= 4)` 一旦不成立就进入 `else` 分支, 丢弃散布角（`xRot` 换成玩家视角、`yRot` 不带偏移）⇒ 三箭轨迹完全重合、满伤圈不再受几何限制（见表末行与 D12）。

| converge 等级 | 单箭偏移角 | 三箭全中极限距离 | 备注 |
| --- | --- | --- | --- |
| 0（裸弓） | ±10° | **1.70 格** | 基准。mixin 在 0 级也换平面, 故不是垂直 5.39 格 |
| 1 | ±8° | 2.13 格 | 正收益 |
| 2 | ±6° | 2.85 格 | 正收益 |
| 3 | ±4° | 4.29 格 | 正收益 |
| 4 | ±2° | **8.60 格** | 满级收益, 上限必须卡 4 |
| 5 及以上 | ±0°（完全沿准心） | **∞（不受几何限制）** | **完全收敛, 不是降级**：`else` 分支丢弃散布角, 三箭轨迹重合；满伤圈只受箭速衰减与瞄准精度限制。等于取消距离分层, 故配方上限锁 4（8.1 ②、D12） |

**大碰撞箱目标**（凋灵 / 末影龙 / Boss 类, 半宽 0.6~1.0）：容差 = 半宽 ⇒ 裸弓满伤圈 3.4~5.7 格、converge 4 到 17~29 格（实际受箭速衰减与精度限制）。⇒ 对 Boss 的远程优势本就存在, 属合理的体型溢价, 不需要额外平衡干预。

**这张表说明的三件事**：

1. **裸弓的 85.7 只在 1.7 格内成立**, 比近战 3.0 格的判定距离还近。也就是说「贴脸弓强」的物理基础是「弓口顶着怪」, 这正是旧版 150 DPS 的场景；削减后两侧同为 85 档, 贴脸从「弓的绝对优势」变成「近战略优」。
2. **converge 从可选 build 升格为弓的存在理由**：不装它的弓只在 1.7 格内有满伤, 1.7~3.0 格被近战碾压, 3 格以外掉到 28.6。装到 4 级才有 8.6 格的满伤圈, 这才满足「远程武器」的定义。故第五章把它列为首推流派而非锦上添花。
3. `(5 − L)/5` 的线性缩放使 1~4 级每级都在扩大满伤圈（2.13 → 2.85 → 4.29 → 8.60）, 而 5 级不是「退回垂直」而是**完全收敛** —— `else` 分支把 `xRot` 换成玩家视角、`yRot` 保持无偏移, 三箭轨迹完全重合, 满伤圈不再受几何限制。**这等于取消距离分层（与 m00475 的裁定 4 冲突）, 所以必须用配方上限把 converge 锁在 4 级**（`Modifier.js` 一行）。这不是修 bug, 是主动设闸门（D12）。

### 9.2 风险清单

- **R1 数值双源不同步**：弓曲线在 `TConMaterial.js`, 近战曲线在 KubeJS 修饰符, 两处独立维护。缓解：在 `TConMaterial.js` 顶部与 `TConModifiers.js` 顶部互相注释指向对方, 并在 `Developer/planning_documents/2.6.0/` 留一份「锚点常量表」（86 / 85.7 / 单箭 20）。
- **R2 与既有 Nebula 机制叠乘**：`acupoint`（血量斩）与所有技能的追加段叠加会形成「残血秒杀链」；`killing_rhythm` 与 `precision_strike` 两个节奏类增益叠乘会把剑推到 110+。缓解：8.4 的「追加段不吃按目标当前血量计算的效果」必须在代码层实现（`onDamageDealt` 里判断 `isDirectDamage`）, 不能只写在文档里；按 m01817, 载体材料只给 `head`, `precision_strike` 与 `killing_rhythm` 在材料层就不可能挂到同一条主刃上（前者是铬的 trait, 后者是独立修饰符）。
- **R3 溅射强化的群体极端值**：m01984 后它只挂在劈刀与镰上 —— 劈刀 6 目标 262.1（与弓 265.7 基本持平）、镰（工具）126.4。真正需要防的是**日后有人把红钕挂到高攻速武器上**：若给剑（单体 85.0）开溅射, 6 目标会到 390 以上。四道闸：溅射目标数封顶 8、光爆段不吃任何「按目标数追加」的效果、`cmi:quake_core` 的震荡在波及 ≥5 时不触发、类型闸门（6.7）只让自带生物 AOE 的武器生效。
- **R4 `heavy_edge` 的全局通胀**：material trait 会同时作用于该材料的**所有**工具（剑/斧/锤/镰/镐）, 而其他模组的近战武器吃不到。缓解：tier2 不挂、tier3 只 1 级、tier4 只 2 级（封顶 +3.0）, 并把「非 TCon 近战武器拿不到基线」记入 11.1 待裁定。
- **R5 数字通胀**：86 锚点意味着单击要打出 85~100 点, 屏幕上会出现 200+ 的数字, 原版血条（20 点）失去参照意义。这是「贴脸同档」的必然后果, 不是 bug, 但需要同步考虑怪物血量与整体数值体系（**超出本次范围**, 记为 11.2 D13）。
- **R6 floor 与低 tier 材料错配**：`echo_slash` 的 floor 是「每段 8 点」（floor 10 会让匕首到 104、超锚点 21%, 故压到 8）, 按 tier4 单击校准。若玩家用 tier1 材料（木头剑单击 4）装上同技能, floor 会凭空多出 40 点。缓解：`floor` 改为 `min(8, 0.3 × 单击值)`, 让低基础武器按比例走。
- **R7 converge 改造的回归风险**：把散布从水平搬回垂直, 会让「横向并排的多目标」变差、「纵向单体」变好。这是**有意为之**（单体是弓的主战场, 多目标是近战的生态位）, 但需要在 5.2 明示, 避免玩家以为是 Bug。
- **R8 技能等级被强化件突破**：所有技能本体等级由材料固定（1~4）, 强化件只改参数（窗口宽度、段数、回灌倍率、破防幅度）。必须在 `TConModifiers.js` 里禁止强化件写入技能本体的 `volatile_int`（技能等级不读 volatile, 直接读 `getModifierLevel`）, 否则「材料技能 + 强化件叠级」会让乘数二次爆炸。

## 十、实施顺序与推荐

### 10.1 推荐顺序（六步, 每步可独立验证）

- **第 1 步（弓材料参数）**：`TConMaterial.js` 三处 `limb`（不锈钢 `(-0.05, 0.2, 800, 0.3)`、戴斯 `(0.15, 0.25, 1280, 0.6)`、紫金 `(0.35, 0.25, 1420, 1.1)`, 工业铁不动）。验证：四级**单箭 = 8 / 10 / 14 / 20**、射速 **1.333 / 1.333 / 1.429 / 1.429**（全部 ≥ 现状, **没有任何一处削射速**）。
- **第 2 步（多重射击限级）**：暗影钢 `ranged multishot 2 → 1` + 四级弓臂各挂 `multishot 1`。验证：N 上限从 **5 回到 3**, 四级贴脸 = **32.0 / 40.0 / 60.0 / 85.7**；对照现状（暗影钢 + 紫金 = 157）⇒ **这一步独立完成了主削减, 弓侧到这里就已经收口**。
- **第 3 步（converge 限级）**：`Modifier.js` 的 `level(1,5) → level(1,4)`, 一行、零 Java 改动。验证：满伤圈 converge 1/2/3/4 级 = **2.13 / 2.85 / 4.29 / 8.60 格**（裸弓 1.70 格）, 5 级不再可获得。5 级及以上是完全收敛（三箭轨迹重合、满伤圈不受几何限制）, 锁在 4 级是主动设闸门以保住距离分层。**这一步是弓的第一条 build, 也是「提高泛用性」的落点。**
- **第 4 步（载体材料 + 近战基线 + 八个技能）**：先按 8.2 ⑤ 注册七个载体材料（六个 `head`、以太 `limb`）并挂标签, 再挂技能（铬 `precision_strike 4`、钨钢 `echo_slash 1`、红钕 `glow_splash 1`、铂 `guard_break 1`、钒 `execution 1`、钛 `impale 1`、以太 `volley 1`；`heavy_edge`：tier4 全部 2 级、tier3 全部 1 级）, 最后写 `TConModifiers.js` 的技能本体（含第 1 层武器标签判定与第 2 层材料唯一性检查）。验证：剑 **85.0（精准）/ 85.8（回声）**、匕首 **85.8（回声）**、短柄斧 **82.0（处刑）**、标枪 **84.7（投掷穿刺）**、弩 **86.1（装填齐射）**、劈刀 **57.1（溅射）/ 61.3（破防）**、镰 **82.5（精准, 3 目标）**、板斧 **67.9 / 大锤 57.2（破防）** ⇒ 单体档六件 82~86 与 L4 弓 85.7 同档, AOE / 团队档按 D18 兑换；并验证「钨钢做不出手柄」「用两种技能材的劈刀两个技能都失效」「标枪投掷不吃近战技能」「长弓吃不到装填齐射」。**`heavy_edge` 必须先于技能上线, 否则技能做出来只有 74。**
- **第 5 步（强化件）**：十五个强化件 + 获取配方。验证：剑 **97.8（精准）/ 112.2（回声）**、匕首 **112.2（回声）**、短柄斧 **92（处刑）/ 标枪 94（贯穿）**、弩 **106.7（装填齐射）**、劈刀溅射档 **70.6（3 目标 151.2）**、板斧 **67.9（团队 +40%）** ⇒ 单体档十件落在 92~112, 重武器落在 57~68（D18 的取舍, 不追 110~130）。
- **第 6 步（复测与收口）**：全武器复测六档距离、核对第七章矩阵；确认 `point_blank` 与 `converge` 的互斥生效（代码层读等级即唯一约束；槽位层不可依赖, 见 5.1）, 并确认 `converge` 在合成界面与指令两条路径上都拿不到 5 级。

### 10.2 推荐组合

- **弓侧：材料上调（第 1 步）+ 多重射击限级（第 2 步）必须一起做**。只做上调会变成 157, 只做限级则毕业弓单箭只有 15（不足 20）。**不做 B3 递减、不做 N2 共帧、不做断电** —— 它们都会把 L4 打到 28.6~65.2, 与 86 锚点冲突。
- **弓侧的第一条 build 是 converge（第 3 步）**, 因为它恰好补在「裸弓 1.7 格之外只有 28.6」这个最痛的空档上, 而且是纯横向（只改距离、不改伤害）, 永远不会破坏锚点。第二条是 `point_blank`（贴身散射）, 与它**互斥** —— 弓永远只有一条 build 生效, 这是刻意的设计约束, 不是遗漏。
- **近战五个技能 + 远程三个技能全做, 不要只做两个**。它们分别挂在七个新注册的载体材料上（铬 / 钨钢 / 红钕 / 铂 / 钒 / 钛 / 以太）, 天然并联 —— 材料结构上不可通吃（一把剑只有一个主刃, 刃用什么材料就只有一种）, 玩家的选择是「选哪种材料 = 选哪个流派」, 这正是 m01056 要的 build 结构。**按 m01817, 冲突进一步前移到材料层**：载体只给 `head`、武器 / 工具用物品标签分流、材料唯一性检查兜底（6.2b）, 所以「互不挤占槽位」不是约束（槽位可无限买, 见 5.1）, **材料才是约束**。只做两个会让另外两个载体变成纯数值材料, 流派设计失去意义。
- **强化件分批上线**：先做参数型（`tempo_window` / `echo_delay` / `splash_focus` / `sunder`, 都是改一个数）, 再做能力型（`precision_edge` / `echo_lance` / `quake_core` / `hammerfall`, 需要新逻辑）。参数型风险低、能立刻验证投入档位差是否如实落在 110~130。
- **不建议本期上 `hammerfall` 与 `quake_core`**：两者的目标（锤专精、震荡）已经有 `guard_break` 与 `glow_splash` 覆盖, 先看实测数据再决定是否值得多两个能力槽的复杂度。

### 10.3 不推荐的做法

- **直接把近战 `attack_damage` 翻 3 倍**：tier4 剑单击会到 40+, 普通怪全部秒杀, 且与弓的「每秒命中次数」差异依旧存在（6.9 已否证）。
- **把 `multishot.json` 的 `each_level` 改成 1**：会让 1 级从 3 箭变 2 箭、2 级变 4 箭, 是**全局削弱所有弓**（包括原版匠魂弓）, 而不是限级。正确做法是限制等级上限（暗影钢 2→1）。
- **取消 multishot**（`each_level` 归零）：会削掉弓的识别度, 玩家会觉得「武器被砍废」而不是「被平衡」。
- **给弓加距离衰减系数**：裸弓的几何衰减已天然存在（3 箭固定 ±10° 水平分离, 超过 **1.7 格**只中中央一箭）, 再造一层是重复设计。
- **取消清零点**（N3 断电）：会把 L4 打到 28.6, 违反「毕业弓单发 ≥20」与 86 锚点, 需要把弓的 `projectile_damage` 加到 +40% 才能补回, 代价更大。
- **让强化件提升技能本体等级**：会造成「材料技能 + 强化件叠级」的乘数二次爆炸, 见 R8。
## 十一、待裁定（D1~D22）

- **D1（已收敛, 留档）**：锚点由您两次裁定确定 —— 单发 ≥20（m00641）与毕业近战 ≈86（m00786, 因 1 级多重射击 = 3 箭）。二者反解出**唯一**可行组合：紫金 `velocity 0.7→1.1`（单箭 20）+ N 上限 3 + 保留清零点全结算 ⇒ **L4 贴脸 85.7**。B3 递减（65.2 / 52.4）、N2 共帧、N3 断电都因这条锚点被降级为「日后旋钮」。
